# 11 · 没有被本包证明的事

- 原作者没有连接29；本次整合只读核对29服务/GPU/保护文件及P6二进制，没有执行GPU测试、编译CUDA候选、改变生产或升级Strata。离线工具验证只是工具验证。
- 用户仓库报告可读，但很多workspace原始SSE/trace/raw/logit不在公开tree。本包不声称独立重算全部P3/P24原件。
- 外部最新source SHA已固定；tag名称、GitHub发布日期、source commit和本机二进制可能不同。来源表不是安装清单。
- 作者/社区的tqLLM、HyperQwen、Edge0、Maya速度不属于本机结果；不同模型、量化、CPU、RAM、上下文、采样、输出长度和版本不能相减当可得收益。
- 没有发现可直接实施的新warm decode候选，不等于证明软件达到全局最优。十二张卡中多数是覆盖审查、延期或未来条件分支。
- “无损格式”“精确top-k”“spec验证”都不是整机bit-exact或任务成功的充分条件。
- E0可以支持基线行为保持，却无法修复基线已有六项长检索错误；正式质量仍是独立阻塞。
- 低样本配对区间有适用限制，不能声明全天稳定、可靠p99、所有任务非劣或未来版本不回归。
- P24的major fault和swap不证明其性能回退由内存导致。任何新内存方案都需要当前归属/等待证据。
- 完整raw采集或再训提前路由会消耗大量内存/时间；不作为默认必做。缺依赖时如实BLOCKED，而非取消硬门。

所有新增收益估算均是显式条件公式；没有“预期+20%”等未经本机证据支持的承诺。方案可以完整执行后得出零收益候选，此时交付负结果和资源保护证据即完成该轮任务。

正式P05目前还缺本轮稳定warm fixed2048探针的实物资格证据。自然prime不同会使append输入不同；只冻结配方或seed不够。先验收已有原件，缺失即不启动P05；不能借严格统计工具的格式通过掩盖实际不可比较。
