## 一票否决顺序

1. 与已关闭项没有机制差量，或当前路径已实现→`COVERED/NO_NEW_DELTA`。
2. 依赖未支持硬件、缺资产、没有实际调用→`NOT_APPLICABLE/BLOCKED_EVIDENCE`。
3. 只知道累计kernel时间，依赖或窗口不闭合→`INSUFFICIENT`。
4. 乐观可省比例<4%→关闭本次资格；4%–8%之间通常没有足够改造余量，保持不足，不自动写kernel。
5. 首选能证明≥8%暴露份额且有可信局部方案的方向；按实测/可信微原型速度s和新增成本计算净空间≥4%。不能任填s=2。
6. RAM/VRAM/上下文/温度/实际dispatch合同破坏→`BLOCKED_RESOURCE/REJECTED_NUMERICS`。
7. E1/Q仍缺绝对质量与相对非劣前提→`DEFERRED_QUALITY`，只做源码设计。

4%与8%是本包的**新工程筛查政策**，不是实测改善、统计显著性或物理定律。关键路径归因不充分时即使比例高也不能晋级。

## 候选选择不是打分游戏

不用未经证实的“收益30分、可行性20分”合成精确排名。先硬门，再在合格项中比较：暴露成本下界、机制差量大小、数值证明复杂度、额外内存、改动文件数量、回滚独立性。只选择一项；其余留在原状态。若主要成本是不可消除CPU/DDR工作而所有变化只影响隐藏分支，允许零候选收口。

## 有限组合的条件

只有两个独立候选各自在同一B、相同工作负载、无profiler下通过正式性能与质量门，才做2×2相互作用实验。若修改同一个dispatch/slot/scratch子系统，必须先解决语义与资源冲突。禁止把边缘1%项相乘凑4%，也不把A0→P6升级收益计入候选。
