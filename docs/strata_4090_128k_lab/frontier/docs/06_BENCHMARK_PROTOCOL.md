本包最后一行是**新政策**，不能追溯重判旧报告。本轮warm decode主指标先固定为decode_ms；A/A噪声定义为预登记独立配对的同一主指标time ratio相对1的绝对偏差中位数；同工作负载/基线的已有合格A/A可复用。只有一次off/on诊断不能估噪声。没有合格A/A则正式性能不得开跑，先在P05登记最小独立校准，不能观察候选后再选噪声。

## 指标定义

固定输出性能探针：完整decode开始到结束、真实committed token数、ms/token；TTFT、完整wall分别报告。输入、输出token数/请求hash匹配且实际fresh/warm链成立，才进行该探针的配对。

真实采样任务：不强制两臂输出相同长度，以独立任务成功与预算内wall衡量；同时报告所有thinking/正文token、错误与完整ms/token。不能用更少输出、早EOS或失败快来宣称更快。真实任务不喂入“要求同输出长度”的离线固定探针工具。

任务restricted time：`t_i*=min(实际成功时间,事前任务预算B)`；未在B内成功（含模型断言失败/任务预算耗尽）记B。基础设施错误使实验失去资格，不能从幸存任务计算采用结论。P3专用chain工具已有失败按2400s的做法；通用正式适配器仍需实现并验证，不声称已有完整统一能力。

## 阶段和总量

P01限额诊断不作显著性。P03每Task做最小代码/关闭路径验证。P04做候选相关数值/资源/生命周期。只有均通过才P05。

P05主场景建议冻结100K级warm append、fixed2048 output，六对fresh-engine，AC/CA/CA/AC/AC/CA。每臂prime+append，所以12引擎/24工作请求。prime是建立同状态的支撑步骤，不当主指标。若baseline无法稳定达到fixed2048或warm合同，则本probe不具资格，不用截断/重试制造完成。

主门通过后，支持场景4K与120K各两对（各臂同样prime+append），增加8引擎/16工作请求；主与支持共20引擎/40工作请求。若还需要3对A/A校准，则本Phase上限增至26引擎/52请求；该数不含P01、P04及独立质量/热测试。支持层只做描述性支持与异常筛查，不建立正式2%统计非劣，也不并入主六对。120K渲染输入最多122880，输出预算与4096余量仍须实际核算。若某候选只作用prefill，这属于另一个预登记campaign，不能拿本轮warm结果失败后换TTFT主指标救活。

### warm探针的开跑前资格门

自然prime会把实际生成历史带入append，现有记录已表明跨引擎输出可能不同。正式P05（包括新增A/A）启动前，必须有与B、模板/tokenizer、采样/PT0和本场景一致的稳定探针原件：实际prime历史、完整append body/token hash、真实warm read/reuse、自然fixed2048输出均满足合同。当前资料没有替本轮证明这一资格；缺证据即BLOCKED_EVIDENCE/NOT_RUN，不启动主十二引擎，也不自动搜索容易稳定的新题。

历史资格不能保证新臂。每个prime后、发送append前再次核实际完整请求hash；首次不符立即停止并保留消耗，整批INSUFFICIENT，不替换真实历史、不重试。工具的单一request_sha256必须是实际请求身份，不能换成recipe hash绕过。

若原有已验证接口能从冻结transcript或兼容状态建立同一KV/GDN/PLE/MTP状态，可以另立受控warm replay实验。它只回答固定状态下的引擎成本，不冒称自然prime→append收益或任务质量；没有现成接口就保持阻塞，不为完成本计划新造大型harness。自然质量任务始终用真实历史，另按成功与预算封顶时间评价。

首次正式候选前，冻结选择集/留出集和工作分布。多个候选不得共用被挑选过的结果作独立留出；本包默认仅一个候选。

## 整对统计

对第i对计算`r_i=C_i/A_i`、`l_i=log(r_i)`，点比`exp(mean(l_i))`。6对采用完整6^6=46656整对bootstrap，双侧95%百分位区间；同引擎内多个请求、token、窗口不是新的重采样单位。

这是有限工程证据，n=6并不保证未来负载代表性或稳定覆盖。若区间太宽则INSUFFICIENT，不能选做更多样本直到显著。扩大样本必须事前新计划，并完整保留本轮结果；不把两轮混成一轮无条件显著性。

`tools/paired_stats.py`是离线固定探针的完整性与时间门计算器。质量、任务成功、冷却、部署均独立。其输入的hash/实际执行声明需要原件审计，工具不能证明输入真实性。

## 运行纪律

- 正式臂删除计时/profiler/oracle/managed诊断开关，不能仅设0；有些env检查存在即启用。
- 不同native build、模型、template、缓存预算、thread map、采样或主机设置不得混配。A1关闭路径先验证无副作用。
- 不下载trace/压缩归档与正式测量并行；资源采样低开销且所有臂一致。
- 初始温度/冷却标准在预登记中固定；不锁频后与旧未锁频混算，也不按时钟事后归一化挽救结果。
- 所有失败、短输出、hash不符、swap/fault和温度记录保留。失败不能替补；资源门触发时整个候选本轮无资格。
- p95/p99只在足够请求样本时讨论；20引擎不能给“全天稳定”或可靠p99承诺。
