# P0-T5 报告：decode 诊断构建（DIAG）（2026-10-25）

**结论：**

1. 29 上一个 decode 窗口约 18.5 ms，其中 90% 是 verify。verify 内部：等 GPU 约 9.4 ms（窗口的 51%），CPU 专家池约 6.6 ms（36%）。另有 MTP draft 1.6 ms（9%）。
2. #1864 补进来的 adaptive wait / join，加上 commit / other，合计不到 0.3 ms（约 1.5%）。所以窗口里没有“看不见的”大块耗时，0.1.43.1 时代估的 17～18 ms 拆分基本可信。
3. verify 窗口的 token 数 T 集中在 4：T=4 占 66%，T=1/2/3 各占 10～12%，T≥5 只占 0.4%（全部是 prompt-lookup 窗口）。
   - 因此 dense 投影的 2～4 列路径（IL 表）决定 GPU 侧小矩阵的速度。
   - 5～8 列的表在 `--spec 4` 下几乎用不到。
4. `mmvq_il_parity` 在 4090 上逐位一致。实测的 sm_89 表和源码给 sm_89 用的共享表（`kIlRowsShared`）有 14 个格子不同。不过在 T=4 下，IL 路径比 `native_mmvq` 多列 kernel 普遍快 5～13%。
   - 推断：CFG-IL0（关掉 IL）在 A0 上大概率是退步，不会重现 Issue #1842 在 0.1.41 上看到的长上下文收益。仍按协议实测（P0-T6）。
5. `STRATA_PREFILL_CPU_SHARE_MAX=3072` 生效（源码确认）。启动日志里的 “below 1024 tokens” 是写死的字符串，不反映实际值。

DIAG 不是 A0，下面的数字不进入任何 A/B 配对统计，只用来判断后续实验的空间。

最慢的 10 个窗口有两类：

## 3. 按窗口 token 数 T 拆分

| T | 窗口数 | 占比 | 接受 token | 总 ms | verify | 等 GPU | CPU 池 | draft |
|---|---|---|---|---|---|---|---|---|
| 1 | 490 | 12.1% | 0 | 12.59 | 11.15 | 8.09 | 2.46 | 1.22 |
| 2 | 466 | 11.5% | 0.72 | 15.12 | 13.41 | 8.62 | 4.18 | 1.47 |
| 3 | 405 | 10.0% | 1.39 | 17.77 | 15.97 | 9.11 | 6.15 | 1.52 |
| 4 | 2,675 | 66.0% | 2.23 | 20.18 | 18.20 | 9.80 | 7.77 | 1.72 |
| 6 | 16 | 0.4% | 3.50 | 40.72 | 38.36 | 10.75 | 26.81 | 1.91 |

T 从 1 到 4，等 GPU 只增加 1.7 ms（+21%），CPU 专家池增加 5.3 ms（约 3.2 倍）。

- 推断：多 token 的 verify 主要贵在 CPU 专家，因为不同 token 路由到更多不在 VRAM 的专家；GPU 侧对 T 不敏感。
- 这说明继续加大 GPU 侧 dense 并行（例如更宽的窗口）收益有限。CPU 专家路径才是 T=4 窗口的边际成本。这是 P0-T7 / NP-0 要量化的方向。

5～8 列：sm_89 没有 `kIlRows58` 表，走 multi kernel；实测表在 T=5～8 有可观收益（head T=5 576.9 → 478.9 µs）。但在 `--spec 4` 下 T≥5 只占 0.4%，不值得改源码。

## 7. `STRATA_PREFILL_CPU_SHARE_MAX=3072` 是否生效

源码（A0 `src/prefill/prefill.cpp` `cpu_share_max()`）的逻辑：

- 变量已设置时，取 `max(1024, 3072)` = 3072。
- 只有“share 默认开启、`STRATA_PREFILL_CPU_SHARE` 未设置、且 MAX 也未设置”时，才退回 1024。

生产设置了 MAX，所以 3072 生效，作用是低于 3072 token 的 prefill chunk 走 CPU share。启动日志 “ON by default for prompt chunks below 1024 tokens” 是 `arm_cpu_share()` 里写死的字符串，不读实际值。

这是源码确认，没有做运行时开关对照。之前（10 月）的 A/B 已经测过效果。
