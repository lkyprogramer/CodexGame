# P0-T6 报告：A0 配置对照（CFG-IL0 / CFG-IL89 / CFG-EXACT）（2026-10-25）

**结论：**

| 对照 | 结果 | 决定 |
|---|---|---|
| CFG-IL0（`STRATA_MMVQ_IL=0`） | 引擎 ms/窗口 −0.1%，decode 各组中位 0.980～0.995，CI 都覆盖 1；短、长上下文都没有方向性差异 | **不采用**。Issue #1842 在 A0 上不复现 |
| CFG-IL89（`STRATA_MMVQ_IL_ROWS` = 4090 实测表） | 引擎 −0.56%（小于 A/A 的 0.75%），decode 中位 0.987～1.005 | **不采用**；#3453 的 Ada 表收益上限同样很小 |
| CFG-EXACT（7 个 exact 开关） | 引擎 17.30 → 16.54 ms/窗口（−4.4%）。greedy decode：短 +3.9%、长 +5.4%（CI [1.014, 1.066]）；采样 +1.8% / +4.0%。质量 89/90 对 89/90 | 通过质量门 |
| drop-one：CPU_IQ_ALL_EXACT1 | 在其余 6 项之上再开：CPU 专家 +0.15 ms，ms/窗口 +0.95%，decode 中位 0.98～1.007；与 EXACT 那轮的 +0.17 ms 方向一致 | 去掉 |
| **公共基线** | **A0 + EXACT6**（`SIDE_MIXER=2 ATTN_DAILY=1 GR_UP75=1 GU_SWIGLU=1 QSA_ROWS=1 B6_MMVQ_ROWS=1`）：16.43 ms/窗口，A0 约为 17.30～17.42 | 已写入实验配置 `extra_frozen_env`，后续所有 arm 共用 |

组合对照（CFG-IL0 + CFG-EXACT）按规则不做：CFG-IL0 没有通过。

生产没有改动。EXACT6 进入生产是另一个候选变更，需要你审批，见第 7 节。

## 1. 设置

| 项 | 值 |
|---|---|
| 基线 | A0（`5c8dd322`，`819ff262…de3d`），生产归一化配置，与 MIG 相同 |
| 方式 | runner `cfg` 模式：每轮 base / cfg 两个新进程，偶数轮 base 先、奇数轮 cfg 先；5 轮 |
| 题集 | `decode-1c99c03c6c9e`（14 题，本轮新建）：<br>- 短 prompt 固定 512 输出 3 题 + Pi 采样副本 3 题（取自 MIG 题集）；<br>- 长上下文代码生成 4 档（3,938 / 32,612 / 65,389 / 122,749 token），每档 greedy 与 Pi 采样（1.0 / 0.95 / 20）各 1 题，全部固定 512 输出 |
| 质量组 | CFG-EXACT 另跑 `mig-523966959432` 的 quality / tool / protocol 共 18 题，5 轮 |
| 时间 | 02:42～05:15 EDT，6 个 campaign，共约 1,000 个请求，全部完成，无中断 |

新题集的原因：MIG 题集里的长上下文题只生成 117～139 token（模型答完就停）。新题让模型就 ledger 写 Java 实现，烟测和正式运行中 4 档都稳定生成满 512 token。

## 2. A/A 噪声（两个 arm 都是 A0）

| 指标 | base | cfg | 差 |
|---|---|---|---|

| CPU 专家 | 4.551 | 4.431 | −2.6% |
| token/窗口 | 2.790 | 2.781 | −0.3% |

| 组 | decode tok/s 配对中位（cfg/base） | 95% CI |
|---|---|---|
| decode | 1.007 | [0.984, 1.043] |
| decode-sampled | 1.008 | [0.990, 1.040] |
| long-decode | 0.990 | [0.972, 1.005] |
| long-decode-sampled | 1.021 | [0.969, 1.067] |

单题的 5 轮中位最多偏离 ±6%。判定以组级配对中位 + CI 和引擎 ms/窗口为准；本轮实测的引擎级噪声约 ±0.75%，组级约 ±2%。

**一个影响后续门槛的事实：greedy 输出跨进程不可复现。** 同一 A0 二进制、同一配置、同一请求，两个进程的 greedy 文本只有 6/35 完全相同。分叉总落在少数固定位置（例如第 52、129、205、1293 个字符），即近似平票的 token。同一 arm 的 5 轮之间也有 3～5 种不同文本。

- 推断：专家落在 VRAM、CPU 还是 adaptive tier，取决于进程的缓存状态；GPU 与 CPU 专家的累加顺序不同（源码有 `--expert-cache-cpu-order` 实验开关），所以会产生末位差异。
- 后果：协议里“首 token logits / 输出逐位一致”的身份门在 29 上不可用。按协议的备用规则，改以质量 / 工具组全部通过为门。

### 5.1 drop-one：CPU_IQ_ALL_EXACT1

基线 = A0 + 其余 6 项（`config/local-exact6.private.json` 的 `extra_frozen_env`，已从引擎进程 `/proc/<pid>/environ` 确认）；cfg = 再加 `STRATA_CPU_IQ_ALL_EXACT1=1`。

| 指标 | 6 项 | 7 项 | 差 |
|---|---|---|---|
| ms/窗口 | 16.430 | 16.586 | +0.95% |
| CPU 专家 | 4.501 | 4.654 | +0.15 |
| 等 GPU | 8.891 | 8.911 | +0.02 |
| decode 中位 | — | 0.979～1.007 | CI 覆盖 1 |

两轮独立数据里，它都让 CPU 专家慢 0.15～0.17 ms，与 A/A 中 CPU 项的 −0.12 方向相反。

- 上游开这一项的依据是 A4000 −3.3 / 3060 −0.6 个点，是在 AVX-512 VBMI 或不同 CPU 上测的。29 的 Xeon 4216 没有 VBMI，专家 kernel 走 AVX2。
- 结论：在 29 上不带来收益，去掉。

## 6. 采用判定

- 协议写的门槛是“decode 收益超过 A/A 噪声（约 5%）”。这个 5% 是写协议时按旧数据估的；本轮实测 A/A 为引擎 ±0.75%、组级约 ±2%。
- EXACT6 相对 A0 的引擎耗时 −5.3%（16.43 对 17.30～17.42），greedy decode +4～5%，长上下文 greedy 的 CI 不含 1。质量、工具、协议门全部持平。
- 判为通过，作为公共基线。所有后续 arm（含 PR 的 base / off / on）都带同样的 6 个 env，不只给某个 arm 加。
- 质量组是用 7 项跑的。6 项是它的子集，去掉的 CPU 开关让 CPU 路径回到 A0 默认，不需要再单独跑质量组。

## 7. 生产候选（需要审批，本轮未改）

在生产 `strata-iq3_xxs.json` 的 env 中加入 6 项：`STRATA_SIDE_MIXER=2`、`STRATA_ATTN_DAILY=1`、`STRATA_GR_UP75=1`、`STRATA_GU_SWIGLU=1`、`STRATA_QSA_ROWS=1`、`STRATA_B6_MMVQ_ROWS=1`。

- 适用版本：本轮只在 A0（v0.2.3）上验证，没有在 0.1.43.1 上测。0.1.43.1 源码里这些变量名是否都存在、语义是否相同，没有核对，所以只能随“升级到 A0”一起上。
- 预期（受控回放，不是真实流量）：decode 约 +3～5%，prefill 不变。
- 回滚：删掉这 6 个 env 并重启。
