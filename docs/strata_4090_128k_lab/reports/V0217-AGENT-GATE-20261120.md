# v0.2.17 B2 任务级配对质量门：尾部跳过 rank 7 对精确路由（2026-11-20）

接 [C01 离线反事实](V0217-C01-OFFLINE-20261120.md)。生产停机期间在 4090 的 lab 端口 18089 上跑两臂，结束后生产自动重启。

## 结论

1. **非劣性成立：NONINFERIORITY_ESTABLISHED。**
   - 生产配置 b2（`STRATA_ROUTE_TAIL_SKIP=7`）对精确路由 ts0（`=0`），305 个独立任务配对，用 [`tools/quality_gate.py`](../tools/quality_gate.py) 判定。
   - 最终通过：b2 296/305（97.0%），ts0 292/305（95.7%）。
   - 不一致的配对：只有 ts0 通过 2 个，只有 b2 通过 6 个。
   - 损害上界 U_harm = 1.62%。预登记的 margin 是 5%；1.62% 也低于原计划的 2% 标准。
   - 首次通过率：b2 257，ts0 260；首次结果不一致的配对是 13 对 16，方向相反，同样在噪声范围内。
2. **所以 rank 7 保持不变，rank 9 不必再测。** [KL 测量](V0217-TAILSKIP-KL-20261120.md)显示 rank 7 的 KL 是 0.047；在任务层面，这一差异没有表现为可检出的退步。
3. **真实任务负载下的速度也得到证实。**
   - 两臂生成的 token 数几乎相同（812,657 对 812,894），可以直接比较。
   - 引擎 decode：b2 134.7 tok/s，ts0 115.7 tok/s，**快 1.16 倍**。
   - 请求总耗时：1.76 h 对 2.04 h。
   - 每窗口耗时：4K–32K 区间 27.0 ms 对 32.7 ms；每层窗口的 CPU 条目 4.9 对 7.4。
   - 与 [迁移报告](V0217-MIGRATION-TAILSKIP-20261120.md)中 c100k 的 1.145 倍一致。
4. **这是本仓库第一套可用的正式任务级配对门**（原状态为"缺 gold 题集，BLOCKED"）。
   - 预登记、驱动和参考解自检都可复用。
   - 后续的开关或版本对照，按 [KL 门](V0217-TAILSKIP-KL-20261120.md)（数值级，灵敏）加本门（任务级）两层判定。
   - 本门只判"不比基线差"，不做绝对质量判定：`absolute_quality_gate=NOT_EVALUATED`，`deployment_approved=false`。

## 题集与协议（预登记 v2，运行前冻结）

- **题源**（均为 GitHub 公开仓库，MIT 许可）：
  - [exercism/python](https://github.com/exercism/python) `479f11b4`：取 practice 中只有一个解答文件和一个测试文件的 141 道题。
  - [openai/human-eval](https://github.com/openai/human-eval) `b9453e8f`：164 道题。
  - 先跑 [Aider polyglot-benchmark](https://github.com/Aider-AI/polyglot-benchmark) 的 Python 子集作试跑段（与 exercism 重合的 33 道，属于难题）。
- **参考解自检**：305 道题的官方参考解在同一隔离容器中全部通过，无题被排除（`REFCHECK.json`）。
- **协议**（仿 aider polyglot）：
  - 第 1 次只给说明和桩文件，不给测试；
  - 失败后把测试输出（最后 40 行）发给模型，再给 1 次机会；
  - 要求整份文件放在一个 python 代码块中。
- **主结局**为"2 次内通过"，首次通过率为次要指标。每题一行配对，单位为独立任务。
- **生成参数**：
  - 采样用服务端默认参数，seed = 1000 + 题号，两臂相同；
  - 每次最多 12,288 个 token，thinking 预算 4,096（`reasoning_budget_tokens`，Pi 也能发送这个字段）。
- **判分**：只在本地 `python:3.12-slim` 镜像中运行。容器参数：无网络、只读根目录、`--pull=never`、512 MiB 内存、1 CPU。
- **预登记内容**：margin 0.05，基线 ts0，候选 b2。
  - 选 0.05 的理由：0.02 要求至少 183 题且零不一致，采样解码下不可能做到。
  - 试跑规则：b2 先跑试跑段，若首次通过率 > 0.85 就判定题集太容易，停下重选。实际为 0.27，继续。
- **服务**：每臂从生产配置复制一份，所有写路径都放到实验目录；STRATA_* 的 state 目录也独立。

### v1 预登记的记录（未删）

- v1 没有 thinking 预算，max_tokens 为 16,384。b2 跑了 6 题，平均每题约 150 s，推算两臂要 15–20 小时，于是停止。当时 ts0 还没有任何结果。
- 停止过程中，第一次 SIGINT 被忽略（后台进程的 SIGINT 是 SIG_IGN）。改为先 SIGKILL 外壳脚本、再 SIGTERM 驱动和自己的服务进程组，GPU 已释放。
- v1 全部文件在证据的 `v1-aborted/` 中。v2 只改了 thinking 预算和 max_tokens，并在预登记中写明原因。

## 局限

- 题目公开，模型可能见过。这影响绝对通过率，不影响配对比较的有效性。
- 都是单文件 Python 题，2 次机会，thinking 预算 4,096。没有覆盖多文件项目、工具调用链和超长上下文。工具调用的可用性由[生产验证](V0217-PRODUCTION-SWITCH-20261120.md)和 [Pi 式模拟](V0217-PISIM-20261120.md)覆盖。
- 305 题、margin 5% 只能排除较大的退步；细微的数值差异看 KL 门。
- 引擎日志中的请求数（485 和 483）多于 HTTP 尝试数（353 和 350），因为 thinking 达到预算后要再续写一段。prodlog 的速度统计不受影响。
