# v0.2.17 B2 生产服务的 Pi 式 agent 负载模拟（2026-11-20）

接 [尾部跳过 KL](V0217-TAILSKIP-KL-20261120.md)。最近没有真实 Pi 使用，所以用公开题目模拟 Pi 式的 agent 会话，直接打生产服务（127.0.0.1:18343，未经 NGINX）。

## 结论

1. **生产在 agent 负载下工作正常。**
   - 16 道题全部通过（隔离容器判分），共 120 个请求，无错误、无取消，单个请求最长 prompt 60K token。
   - decode 速度：4K–32K 区间 141.9 tok/s，32K–64K 区间 143.0 tok/s。与 lab 中新启动 B2 的结果一致（d3k 145.4、c32k 147.7）。
2. **swap 不影响计算的热路径，不需要处理。**
   - 引擎的缺页集中在重启后的前两个请求：共约 8300 次主缺页（约 63 MiB 换入），首个请求多花不到 2 秒。
   - 从第 4 个请求起，主缺页中位数为 0，13 分钟内共 966 次。
   - 期间整机只换出 447 页，没有抖动。引擎 VmSwap 从 415 MiB 降到 339 MiB，被换出的是冷页。
3. **复用率 95%，开销主要在每条新用户消息后的重读。**
   - 同一题内的工具循环几乎全部复用。
   - 每来一条新用户消息，PT0 会去掉之前 assistant 的 thinking，渲染出的 prompt 因此与上一题结束时的 KV 在上一条用户消息处分叉。引擎从驻留的会话里借回到该分界点的前缀（14 次 `borrowed`，每次 0.1–0.2 s），再重读上一题的整个工具循环（2–19K token，2.3–6.5 s）。
   - 这部分读入共 114 s，decode 共 502 s，读入约占 18%。
   - 这是 PT0（`STRATA_PRESERVE_THINKING=0`，与模型原生模板一致）的设计代价，不是缺陷。本次每条用户消息都伴随会话切换，所以无法单独测出"切换"本身的代价；从借回的前缀长度看，分叉点就是上一条用户消息。
4. **需要注意的是内存余量，不是 swap。**
   - 会话缓存的上限是 `--conversation-cache-mib 6144 --conversation-cache-slots 4`。本次很快填满（4 个驻留，5.9 GB，按 LRU 驱逐了 11 次）。
   - 填满后整机 MemAvailable 从约 8.4 GiB 降到 3.6 GiB，测试结束后仍为 3.6 GiB。
   - 引擎有 RAM 下限准入（"skip parking (RAM floor)"），这次没有触发。但本机 swap 只有 977 MiB，若其他服务同时需要 3 GiB 以上内存，会有 OOM 风险。
   - 目前不改。如果这台机器还要跑别的重任务，可以把 `--conversation-cache-mib` 降到 4096 或把 slots 降到 3。代价是切换会话时更容易需要整段重读。

## 方法

- **题目**：GitHub 上的 [Aider-AI/polyglot-benchmark](https://github.com/Aider-AI/polyglot-benchmark)（commit `7e0611e7`）。它是 Exercism 题目，aider 的编辑能力基准用的就是这一套。
  - 选 python 的 16 道中等到难题：wordy、bowling、book-store、tree-building、grep、forth、zebra-puzzle、poker、sgf-parsing、rest-api、two-bucket、go-counting、react、connect、pov、dominoes。
  - 复制题目时去掉 `.meta`（参考解），测试文件只读。
- **agent**：[`pisim.py`](../evidence/v0217-pisim-20261120/pisim.py)。
  - 仿 Pi 的系统提示和 read / bash / edit / write 四个工具，OpenAI chat 加 tools，非流式，服务端默认采样参数。
  - 两个会话 A、B 按题交替。每题在原会话里追加一条用户消息，多题累积成长会话，与 Pi 中多个会话来回切换的用法一致。
  - 每题最多 14 轮，超过 100K 就重置会话（本次未触发）。
- **执行隔离**：bash 只在本地的 `python:3.12-slim` 镜像里运行。
  - 容器参数：`--network none --read-only --pull=never`、512 MiB 内存、1 CPU、128 个进程、60 s 超时。
  - 文件工具限定在工作区内。
  - 判分：题目自带的 unittest 在同一容器里运行。
- **采样**：每 2 s 记录一次整机 pswpin/pswpout、MemAvailable、SwapFree，以及引擎的 majflt 和 VmSwap；每个请求前后再各记录一次。
- **请求拆解**：用 [`tools/prodlog.py`](../tools/prodlog.py) 处理本次的引擎日志片段。为此新增了对 `borrowed` 恢复行的解析，以及驱逐计数。
- **局限**：
  - 系统提示比真实 Pi 短（约 800 token），且没有流式和 NGINX 这一层。
  - 题目是单文件的算法题，工具输出比真实项目小，最长上下文只到 60K，没有覆盖 100K 级的长会话。
  - 题目来自公开基准，模型可能见过，16/16 只作健康检查，不作质量结论。
