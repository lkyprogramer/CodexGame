## 1. 证据、收益与适用性

**来源报告：** RTX5090+NVFP4+约29%expert容量、PCIe share0.25：每verify round14.31→13.51ms，decode169.8→179.5tok/s。不同cache/quant/Linux尚缺全面测量。 [来源](https://github.com/Niko1221/Strata/pull/2964)

**本机判断：NOT_APPLICABLE（生产形态）。** 29 真实流量 PCIe share 中位 0.007（旧记录 0.022 也很低），几乎没有可晋升的fetch；生产开启 `STRATA_ADAPT_OVERLAP=1`，原PR拒绝 adaptive overlap，`qualify` 会按规则直接拦截。不为了让本项可测而关闭 overlap 或把 PCIe share 改成 0.25——那是另一个配置实验，且 overlap 本身带来约 12% decode 收益。只有生产形态以后变化（overlap 关闭且 PCIe share 显著上升）才重新评估。

收益数字不是本包作者4090实测，也不作为验收预设答案。先证明瓶颈存在，然后决定是否继续。

## 3. Phase / Task

### Phase A：机制资格与最小设计

A1：运行doctor与qualify；保存模型、KV、MTP、缓存、CPU/PCIe和内存证据。A2：构造能反映该机制的最小样本，确认不是不相关瓶颈。A3：冻结主指标、off/on语义和资源状态图。**Review Gate A**：条件不成立就NOT_APPLICABLE，不先写大改。

### Phase B：最小移植

- B1：先统计真正从PCIe share读取的热点miss；不适用直接停。
- B2：保持原PR的模式限制：batch、pipeline、adapt-async、overlap、peer/helper、resident-RAM、dma/direct等不能强行绕过。
- B3：admission只替换本窗口不使用且没有in-flight拷贝的cold slot；同步host/GPU residency和lookahead快照。
- B4：保持旧函数签名或兼容overload，避免误伤其他backend链接；记录admissions、重复swap避免量、PCIe bytes。

**Review Gate B**：至少检查主线程/worker、异步copy、缓存身份、取消错误恢复和默认关闭路径。可以并行进行文档/CPU测试审查，但GPU实验只能串行。

### Phase C：失败测试与正确性

- C1：admission候选当前窗口使用/正在换入/路由跳过时不得替换。
- C2：host_res与device table发布顺序、lookahead读旧引用、失败回退。
- C3：模式guard逐项测试，原有默认不变。

要求在未修改A0或关闭路径上看到机制测试失败（对于纯性能优化使用已固定的性能断言/dispatch断言），在候选中通过。不能把缺失测试数据导致的skip计为pass。

### Phase D：实机A/B

- D1：generate路径启用STRATA_ADAPT_FETCH_VERIFY读回并校验expert bytes；STRATA_ADAPT_CHECKRES辅助诊断。
- D2：固定actual expert slots、PCIe份额与adaptive参数；测off/1/2，先以2为主候选。
- D3：主要记录ms/verify round，另外记录accepted drafts，避免不同输出与接受率造成假吞吐提升。

**必须观察到的机制回执：** 非零admission且减少真实RAM→VRAM重复传输；仅打印enabled不够。

**停止条件：** 没有PCIe share/当前模式被拒绝、收益需大幅改变现网策略、读回任何字节不一致时停止。

### Phase E：留出与结论

E1：同一Java mini-agent题集与真实Pi留出任务。E2：按统计协议产出CI、质量、资源与回退报告。E3：写DECISION.md并保留最小补丁。**Review Gate E**：只有经过独立留出验证才能推荐生产，脚本不会自动切换。
