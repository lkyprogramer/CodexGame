## 1. 证据、收益与适用性

**来源报告：** RTX5080的合成23K system-root、淘汰后新会话：复用19456→23346，重读3921→31 token，1691→262ms。是特定root丢失场景，不是所有请求普遍6.5倍。 [来源](https://github.com/Niko1221/Strata/pull/3517)

**本机判断：** 普通prompt checkpoint与跨会话大RAM parking不同，这个修复不要求先开32GiB会话缓存。真正前提是system+tools根越过首个周期checkpoint且经历淘汰。**29 实测：Pi 共享 root 约 12.3K token，低于 main 默认 `prompt_cache_every=16384`；10-14～16 新会话已复用 12275/12470/12520 token**，即当前没有观察到“root 丢失”。main 的 `conv_cache.hpp` 以 chain[0] 作 root 并 pin，cap<2 时不 pin。预期结论 NOT_APPLICABLE；只有 Pi 工具定义增长使 root 越过 16384，或观察到新会话复用显著低于 root 长度时才继续。

收益数字不是本包作者4090实测，也不作为验收预设答案。先证明瓶颈存在，然后决定是否继续。

## 3. Phase / Task

### Phase A：机制资格与最小设计

A1：运行doctor与qualify；保存模型、KV、MTP、缓存、CPU/PCIe和内存证据。A2：构造能反映该机制的最小样本，确认不是不相关瓶颈。A3：冻结主指标、off/on语义和资源状态图。**Review Gate A**：条件不成立就NOT_APPLICABLE，不先写大改。

### Phase B：最小移植

- B1：先确认最新main是否已区分root和chain[0]；若存在等价行为，保留源码/复现证据，标记ALREADY_UPSTREAM。
- B2：移植按真实root length定位index的策略，fallback保留旧规则；不要增加无法跨restore维护的隐式状态。
- B3：原PR没有完整off开关，增加STRATA_LAB_ROOT_PIN仅控制新的root查找/保留逻辑；off必须回到冻结A0。
- B4：保留最近checkpoint、tail pin、单槽、无root、多root信息不完整时的确定性淘汰。

**Review Gate B**：至少检查主线程/worker、异步copy、缓存身份、取消错误恢复和默认关闭路径。可以并行进行文档/CPU测试审查，但GPU实验只能串行。

### Phase C：失败测试与正确性

- C1：所有小链、root在0/中间/缺失、grid早于root、cap0/1/2、多pin与相同时间戳；对照独立参考实现。
- C2：对旧policy跑应失败的新root测试，保存red/green证据。
- C3：缓存导入/恢复/取消后root身份不串会话，丢失root时安全回退。

要求在未修改A0或关闭路径上看到机制测试失败（对于纯性能优化使用已固定的性能断言/dispatch断言），在候选中通过。不能把缺失测试数据导致的skip计为pass。

### Phase D：实机A/B

- D1：先用约12.3K root（`root_target_tokens=12288`，对应29上Pi实测）、18次追加触发churn，再开相同root的新chat；缓存容量与周期全组一致。24K root 只作压力对照，不能作为采用依据。
- D2：扩到64K/96K根仍确保总窗口<128K；实际输入与输出余量由counter校验。
- D3：记录checkpoint命中位置与read tokens；chunk边界变化可能造成末位数值差异，不宣称所有输出bitwise。

**必须观察到的机制回执：** 被保护对象从错误grid切换为真正system-root，根经过churn后仍可复用。

**停止条件：** 实际root未越过grid、main已修复或复现需要人为夸大prompt到超限时停止。

### Phase E：留出与结论

E1：同一Java mini-agent题集与真实Pi留出任务。E2：按统计协议产出CI、质量、资源与回退报告。E3：写DECISION.md并保留最小补丁。**Review Gate E**：只有经过独立留出验证才能推荐生产，脚本不会自动切换。
