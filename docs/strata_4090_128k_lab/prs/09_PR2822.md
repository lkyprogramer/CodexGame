## 1. 证据、收益与适用性

**来源报告：** 旧beta3090、128GB host、32GiB cache：短请求TTFT20.523→0.610s，总吞吐111.29→107.88（-3.1%）。最新版rebase的三对测试是版本比较，不是新的开关收益；不能用于保证所有短请求<1秒。 [来源](https://github.com/Niko1221/Strata/pull/2822)

**本机判断：** 仅当你有主Agent和helper真实争用同一引擎才值得；29 的真实流量来自 Pi，是否存在主/辅助请求并发重叠**尚未统计**，P0 先从请求日志算重叠次数。native parallel仍1，但需要保存暂停的长会话；生产虽有 6144×4 会话缓存，但 MemAvailable 已不足以 parking，剩余RAM是主要门槛。

收益数字不是本包作者4090实测，也不作为验收预设答案。先证明瓶颈存在，然后决定是否继续。

## 3. Phase / Task

### Phase A：机制资格与最小设计

A1：运行doctor与qualify；保存模型、KV、MTP、缓存、CPU/PCIe和内存证据。A2：构造能反映该机制的最小样本，确认不是不相关瓶颈。A3：冻结主指标、off/on语义和资源状态图。**Review Gate A**：条件不成立就NOT_APPLICABLE，不先写大改。

### Phase B：最小移植

- B1：审计最新serve变化，特别是declared_only/预算/自动缓存/错误恢复，不能整段覆盖成PR旧版。
- B2：一刻只允许一个native GEN；STOP排空DONE后才能转交所有权，保留工具调用ID与parser状态。
- B3：设置最短运行quantum和aging，不让短请求洪水饿死长请求。
- B4：使用本包新增实验master或映射真实策略配置，完整off回到A0；先小cache可容纳的32K/64K任务再接近120K。

**Review Gate B**：至少检查主线程/worker、异步copy、缓存身份、取消错误恢复和默认关闭路径。可以并行进行文档/CPU测试审查，但GPU实验只能串行。

### Phase C：失败测试与正确性

- C1：queued/active/paused取消、owner token、450项tool args完整性。
- C2：正在暂停时engine death使受影响stream明确失败，不终止另一个owner。
- C3：缺少/空tools不能经续写漏出未授权调用。

要求在未修改A0或关闭路径上看到机制测试失败（对于纯性能优化使用已固定的性能断言/dispatch断言），在候选中通过。不能把缺失测试数据导致的skip计为pass。

### Phase D：实机A/B

- D1：scenario preemption在长请求真正开始decode后插入短题，确认请求有重叠；三态同样调度位置。
- D2：同时报告short TTFT、long完成、pair wall、总输出量与公平性。
- D3：至少一小时soak和真实Pi helper验证由执行AI补做；长prefill不可抢占的尾延迟必须保留。

**必须观察到的机制回执：** 真正发生STOP→DONE→短请求→恢复，resume prefix不丢、长请求最终完成。

**停止条件：** 没有并发需求、暂停状态放不下、以吞吐严重下降换短延迟、取消跨owner或工具边界损坏时停止。

### Phase E：留出与结论

E1：同一Java mini-agent题集与真实Pi留出任务。E2：按统计协议产出CI、质量、资源与回退报告。E3：写DECISION.md并保留最小补丁。**Review Gate E**：只有经过独立留出验证才能推荐生产，脚本不会自动切换。
