## 3. Phase / Task

### Phase A：机制资格与最小设计

A1：运行doctor与qualify；保存模型、KV、MTP、缓存、CPU/PCIe和内存证据。A2：构造能反映该机制的最小样本，确认不是不相关瓶颈。A3：冻结主指标、off/on语义和资源状态图。**Review Gate A**：条件不成立就NOT_APPLICABLE，不先写大改。

### Phase B：最小移植

- B1：先列出最新main已有loan能力；只扩展缺失资源，不回滚新的内存planner。
- B2：要求solo CUDA、--vram-elastic、至少64MiB segments；拒绝batch/pipeline/split/peer/helper/head-alias。
- B3：保持资源事务原子性：任何阶段失败，要么完整回退原layout，要么失败退出本请求并清洁重启，不能带半恢复状态decode。
- B4：完整恢复图、logit_bias、draft采样、residency同步与PCIe控制。on可改变placement与舍入，不声称bitwise。

**Review Gate B**：至少检查主线程/worker、异步copy、缓存身份、取消错误恢复和默认关闭路径。可以并行进行文档/CPU测试审查，但GPU实验只能串行。

### Phase C：失败测试与正确性

- C1：allocation/capture失败注入覆盖每个步骤，RAII/状态机清理。
- C2：startup/repeat阈值、短追加不触发、错误后健康重载。
- C3：冲突参数启动即拒绝；功能off不分配新大buffer。

要求在未修改A0或关闭路径上看到机制测试失败（对于纯性能优化使用已固定的性能断言/dispatch断言），在候选中通过。不能把缺失测试数据导致的skip计为pass。

### Phase D：实机A/B

- D1：先固定geometry开关对照看事务成本，再auto planner对照看跨档收益。
- D2：测试fresh32K/64K/120K、长消息后的短消息；记录head/graph重建耗时。
- D3：长期多次loan无VRAM碎片或RAM增长，MTP接受率不异常。

**必须观察到的机制回执：** 新geometry确实更好且prefill节省覆盖所有卸载/重载/重建成本。

**停止条件：** 没有planner档位提升、固定geometry负收益过大、后续decode下降超过预先门槛或资源无法安全恢复时停止。

### Phase E：留出与结论

E1：同一Java mini-agent题集与真实Pi留出任务。E2：按统计协议产出CI、质量、资源与回退报告。E3：写DECISION.md并保留最小补丁。**Review Gate E**：只有经过独立留出验证才能推荐生产，脚本不会自动切换。
