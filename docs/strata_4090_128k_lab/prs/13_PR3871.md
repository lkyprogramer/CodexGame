## 1. 为什么对本机重要

- 上游问题（作者报告）：`make_blob` 用 ggml-cpu 的 `from_float` 量化 i-quant 测试行，i-quant 没有该函数 → IQ3_S 等组合直接 SIGSEGV；Q2_0 的 GU / down 用 ggml-cpu 的 Q2_0 dot 计时，而 CPU pool 实际走 Strata 自己的 `q2_rows_any`（`pool.cpp` drain mode 5/6），微基准比 pool 慢约 2.7 倍。
- 本机事实：29 的 CPU 专家有 10 种 GU/down 组合（GU：IQ2_XXS / IQ2_XS / IQ2_S / IQ3_XXS / IQ3_S；down：IQ4_NL 18 层、**Q2_0** 30 层；见 pack 的 `native_experts.txt`）。早先写的“奇数层 IQ2_XXS + Q2_0、偶数层 IQ2_XS + IQ4_NL”只对第 0～4 层成立。NP-1a 就是因为微基准测了引擎不走的 Q2_0 分支，得出“微基准快、整机无益”的错误线索（[NP-0 报告](../reports/P0-T7-NP0-20261025.md)）。
