## 1. 证据、收益与适用性

**来源报告：** 会话缓存的 `ConversationBuffer` 按 16 MiB 分段分配。glibc 的 mmap 阈值是动态的：第一批分段走 mmap，释放一次后阈值被抬到 16 MiB 以上（上限 32 MiB），之后的分段都来自主堆；释放它们只是回到分配器空闲链表，RSS 和 MemAvailable 不变。main 的物理内存门槛（#1347）逐个驱逐已 park 的会话再重读 MemAvailable，读数不动，就会把缓存清空后仍然拒绝。PR 在首次重读前和每次驱逐后调用 `malloc_trim(0)`，并在缺口大于可驱逐字节时直接放弃、不驱逐。独立复现（RTX 3090 / 64 GB / glibc 2.35）：未打补丁的 v0.1.44.1 每次都失败，堆达到 6.9 GiB，一个 214K 快照重读 90 s；打补丁后 3/3 运行都接纳了快照，4K～32K 新 prompt 无代价。trim 单次 37～482 ms（中位约 111 ms，约 80～90 ms/GiB），19 分钟运行 12～14 次共约 2.4 s。已知副作用：两次 trim 之间堆仍然大；trim 后紧接的长 prompt 慢约 2%；残留问题：捕获后的下限检查在 1/3 次运行中丢掉了刚捕获的快照。 [来源](https://github.com/Niko1221/Strata/pull/2253)

**维护者态度：** 2026-10-17 回复“glibc mmap 阈值的发现有用，属于 RAM 门槛的修复而非提速，会作为 bug fix 接收”。

**本机判断：** 29 是本包里证据最直接的一项（glibc 2.36，0.1.43.1）。生产日志 `strata-iq3_xxs.log` 中共 12 次 `skip parking (physical RAM admission ...)`：1 次 `evicted 3, 0 still parked`（把 3 个会话全驱逐后仍拒绝，可用 1301 MiB），11 次 `evicted 0, 0 still parked`（缓存已空，MemAvailable 仍约 1.5 GB，低于 2560 MiB 下限加快照大小）。进程 `[heap]` 约 6.9 GB，与 PR 复现数值一致。**推断**：缓存被清空后释放的分段留在 glibc 空闲链表里，此后每次 park 都会被拒，后续会话切换全部重读 prompt。仅有“放弃驱逐”规则不能恢复 park，真正起作用的是 trim；这一点要在 Phase D 用 `[heap]` 曲线证实。

**不改代码的对照（方案 A）：** `MALLOC_MMAP_THRESHOLD_=8388608` 固定阈值并关闭动态调整，16 MiB 分段全部走 mmap，释放即归还。它与本 PR 针对同一根因，代价是每次 park 新分配的页面都要缺页清零。本项把它作为配置对照 `CFG-MMAP` 一并测量（见 Phase D）；生产是否采用由用户另行审批（MIG-PASS 时随 A0 上线评估；MIG-REGRESS 时可在 0.1.43.1 上另测），本包不改生产。

**与 #3711 的关系：** #3711 有意保留已分配页面来减少缺页，方向与本项相反。先用本项或 CFG-MMAP 让内存有界，再评估 #3711。

收益数字不是本包作者4090实测，也不作为验收预设答案。先证明瓶颈存在，然后决定是否继续。

## 3. Phase / Task

### Phase A：机制资格与最小设计

A1：运行doctor与qualify；记录 glibc 版本、`MALLOC_*` 环境变量（生产未设置）、加载后 MemAvailable。A2：在 A0 上复现“驱逐后读数不动”：cache profile 用生产形态 6144 MiB × 4 slots，用 `--conversation-cache-min-free-mib` 把下限设在加载后 MemAvailable 之下一个可控距离（例如低于加载后读数约 3 份快照大小），让门槛在实验中触发，而真实 MemAvailable 始终高于本包 4096 MiB 安全门。**不得降低本包安全门来复现生产的 1.5 GB 状态。** A3：冻结主指标、off/on语义和资源状态图。**Review Gate A**：A0 上复现不出 `evicted N, ... still parked` 后仍拒绝（或缓存空仍拒绝）就 NOT_APPLICABLE。

### Phase B：最小移植

- B1：移植 `conversation_release_freed_memory()` 与调用点（首次重读前、每次驱逐后）；非 glibc 平台保持空操作。
- B2：移植“缺口大于可驱逐字节就不驱逐”的规则，读数丢失时结束循环（fail closed，与现有门槛一致）。
- B3：新增 `STRATA_LAB_PR2253` 总开关：0 必须回到 A0 的逐个驱逐路径且不调用 trim；1 启用全部改动。
- B4：在拒绝日志里保留 `ram_note()`，另外输出每次 trim 的耗时与 trim 前后 MemAvailable，供 Phase D 统计。

**Review Gate B**：至少检查主线程/worker、异步copy、缓存身份、取消错误恢复和默认关闭路径。可以并行进行文档/CPU测试审查，但GPU实验只能串行。

### Phase C：失败测试与正确性

- C1：`conversation_cache_test`：缺口大于可驱逐字节时不驱逐；pin 的共享前缀不计入可驱逐；读数丢失时退出；off 路径仍逐个驱逐。
- C2：`conversation_memory_test`：trim 函数在 glibc 下可调用、非 glibc 下为空操作。
- C3：在 A0/关闭路径上保存失败（red），候选通过（green）。

要求在未修改A0或关闭路径上看到机制测试失败（对于纯性能优化使用已固定的性能断言/dispatch断言），在候选中通过。不能把缺失测试数据导致的skip计为pass。

### Phase D：实机A/B

- D1：arm 为 A0 / A1 / B，另加配置对照 `CFG-MMAP`（A0 + `MALLOC_MMAP_THRESHOLD_=8388608`，用单独的 local 配置通过 `extra_frozen_env` 注入）。CFG-MMAP 不是 PR arm，不进入配对统计，只做跨 run 的内存指标对比。
- D2：工作负载：至少 3 个 32K～64K 的长会话轮流切换，夹带短请求，至少 30 次切换，5 轮。本包没有内置的 park 压力场景，执行 AI 需新增并测试该场景，或用固定请求序列手动执行并保存请求哈希。
- D3：每次请求后采样引擎进程 `/proc/<pid>/smaps` 的 `[heap]` Rss、`smaps_rollup` 的 Rss 和 MemAvailable（runner 只自动采 MemAvailable）。主指标：park 拒绝次数、驱逐后仍拒绝次数、restore 次数、回访会话的重读 token 与 TTFT、`[heap]` 曲线；次要指标：trim 耗时、park 耗时、decode tok/s。

**必须观察到的机制回执：** A0/A1 出现驱逐后仍拒绝；B 在 trim 后接纳快照，或在 `evicted 0` 时直接拒绝而不清空缓存；`[heap]` 在驱逐后下降。

**停止条件：** main 上复现不出（例如分配器行为已变）、trim 耗时大于省下的重读、快照被丢弃或内容串话、内存持续增长时停止。

### Phase E：留出与结论

E1：同一Java mini-agent题集与真实Pi留出任务。E2：按统计协议产出CI、质量、资源与回退报告；同时写出 CFG-MMAP 的对比结论。E3：写DECISION.md并保留最小补丁。若 CFG-MMAP 单独即可解决且 park 代价可接受，在 DECISION.md 中单列为“对生产的零代码候选”（落在 A0 还是 0.1.43.1 由 MIG 结论决定），由用户决定是否在生产试用。**Review Gate E**：只有经过独立留出验证才能推荐生产，脚本不会自动切换。
