## 1. 证据、收益与适用性

**来源报告：** 旧报告在1740个请求中归因约400秒重复prefill，占约2836秒prefill的14%。这不是最新main或整任务的14%提速证明。PR本身较小，优先证实你的Pi是否有同样的重新编码差异。 [来源](https://github.com/Niko1221/Strata/pull/1536)

**本机判断：** 基本不占额外GPU显存，适合内存紧张环境。**29 实测（10-14～16）：续轮中约 90%（424/473）直接复用上一轮回复，约 10%（48/473）重读回复，合计约 120 s prompt 时间（约占 prompt 15%）**；prompt 只占引擎时间约 20～25%，所以端到端上限约为数个百分点。冻结 main 的 `tools/strata_tokenizer.py` 没有回复 token 复用。先用 token 级前缀比较区分两种重读：BPE 重新编码不一致（本 PR 可解）与 Pi 剥离/改写 thinking 等客户端改动（本 PR 不可解）；后者占多数时判 NOT_APPLICABLE。

收益数字不是本包作者4090实测，也不作为验收预设答案。先证明瓶颈存在，然后决定是否继续。

## 3. Phase / Task

### Phase A：机制资格与最小设计

A1：运行doctor与qualify；保存模型、KV、MTP、缓存、CPU/PCIe和内存证据。A2：构造能反映该机制的最小样本，确认不是不相关瓶颈。A3：冻结主指标、off/on语义和资源状态图。**Review Gate A**：条件不成立就NOT_APPLICABLE，不先写大改。

### Phase B：最小移植

- B1：审计最新PromptEncoder是否已具有等价reply缓存；保留main的新literal保护、工具alias和declared_only逻辑。
- B2：仅保留模型实际生成的token IDs作为可复用边界，确认decode后的文本与再次渲染的输入完全一致；不要以canonical重编码ID一致作为必要条件。
- B3：预算STOP后排空DONE前追加的plain tokens；特殊结束token、未闭合UTF-8、含协议标记的片段不能盲目并入。
- B4：沿用STRATA_REPLY_REUSE开关并新增明确启用回执；功能off不得改变缓存/STOP语义。

**Review Gate B**：至少检查主线程/worker、异步copy、缓存身份、取消错误恢复和默认关闭路径。可以并行进行文档/CPU测试审查，但GPU实验只能串行。

### Phase C：失败测试与正确性

- C1：中文/emoji/组合字符/长数字/Java泛型/字符串转义/BPE非规范分段：decode(kept_ids)==对应prompt文本。
- C2：工具调用参数横跨stream chunk；thinking预算截止、取消、自然停止；不得泄漏推理文本为工具。
- C3：已声明与未声明工具、tools=[]、tool_choice=none、空final各自测试，不能回滚main已有保护。

要求在未修改A0或关闭路径上看到机制测试失败（对于纯性能优化使用已固定的性能断言/dispatch断言），在候选中通过。不能把缺失测试数据导致的skip计为pass。

### Phase D：实机A/B

- D1：真实连续回复后下一轮追加，对比read/reuse token，不能只做预先写死assistant文本。
- D2：执行统一reply-boundary与Java mini-agent；另保留真实Pi日志的长回复样本，脱敏后冻结。
- D3：统计每turn编码时间、重复prefill、完整任务wall；如果重读来自客户端改写/compaction而非BPE，不归功此PR。

**必须观察到的机制回执：** 模型实际生成ID在下一轮复用，原先不必要的re-read减少且文本完全一致。

**停止条件：** 真实Pi没有这类前缀回退，或stream/STOP边界无法证明正确时停止。

E1：同一Java mini-agent题集与真实Pi留出任务。E2：按统计协议产出CI、质量、资源与回退报告。E3：写DECISION.md并保留最小补丁。**Review Gate E**：只有经过独立留出验证才能推荐生产，脚本不会自动切换。
