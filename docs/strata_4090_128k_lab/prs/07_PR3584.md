## 1. 证据、收益与适用性

**来源报告：** 3090/WSL2约9.4K ledger16轮，在“suffix reuse only”与“再加tail/state checkpoints”之间234.2→162.4s；均14/16正确，冷读14.8→20s。最新rebase未重新复现全部-31%矩阵，不能当作128K效果。 [来源](https://github.com/Niko1221/Strata/pull/3584)

**本机判断：** 高潜力但不是免费开关。29 生产已开 `--conversation-cache-mib 6144 --conversation-cache-slots 4`，10-12 有 45 次 parking / 7 次 restore，但 10-15 起因 MemAvailable 约 1.5 GB 低于 2560 MiB 下限被拒——内存才是硬门槛。先测state/checkpoint单份大小与加载后可用RAM（共存容器会占数 GB），再建立所有arm相同的小cache profile；放不下就不适用。

收益数字不是本包作者4090实测，也不作为验收预设答案。先证明瓶颈存在，然后决定是否继续。

## 3. Phase / Task

### Phase A：机制资格与最小设计

A1：运行doctor与qualify；保存模型、KV、MTP、缓存、CPU/PCIe和内存证据。A2：构造能反映该机制的最小样本，确认不是不相关瓶颈。A3：冻结主指标、off/on语义和资源状态图。**Review Gate A**：条件不成立就NOT_APPLICABLE，不先写大改。

### Phase B：最小移植

- B1：逐层移植：先LCP验证的prefix mount，再dense tail，最后state ladder；每层独立开关与内存计费。
- B2：必须同时恢复KV、GDN/递推状态、位置以及draft状态；任何rung高于divergence一律拒绝。
- B3：quantized KV使用其真实格式和边界转换；不能直接按fp16行偏移复制int8/k8v4。
- B4：先与root修复分开；组合时显式处理root pin与ladder淘汰，不覆盖main的缓存内存保护。

**Review Gate B**：至少检查主线程/worker、异步copy、缓存身份、取消错误恢复和默认关闭路径。可以并行进行文档/CPU测试审查，但GPU实验只能串行。

### Phase C：失败测试与正确性

- C1：深度10/30/50/70/90%的插入/删除/替换/完全重放，必须匹配cold recompute。
- C2：stale rung、错误模型/位置/KV格式、预算不足、取消中途恢复fail closed。
- C3：量化块边界、跨层递推状态与draft同步的单元/差分测试。

要求在未修改A0或关闭路径上看到机制测试失败（对于纯性能优化使用已固定的性能断言/dispatch断言），在候选中通过。不能把缺失测试数据导致的skip计为pass。

### Phase D：实机A/B

- D1：先16K/32K再64K/96K/120K；每阶段通过内存门才能增长。
- D2：完整序列wall包含第一次cold额外checkpoint开销；不要只报cache-hit请求。
- D3：记录RSS/峰值/每checkpoint bytes、错误状态命中、Java任务和历史改写后唯一值检索。

**必须观察到的机制回执：** 安全的prefix/state挂载降低实际read tokens，并且冷读+后续turn总时间净改善。

**停止条件：** 装不下一份状态、只能用大内存掩盖问题、任何stale-state正确性失败或冷读成本无法摊销时停止。

### Phase E：留出与结论

E1：同一Java mini-agent题集与真实Pi留出任务。E2：按统计协议产出CI、质量、资源与回退报告。E3：写DECISION.md并保留最小补丁。**Review Gate E**：只有经过独立留出验证才能推荐生产，脚本不会自动切换。
