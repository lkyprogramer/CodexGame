# 明确限制与不能声称的内容

本包初稿作者没有登录用户4090。**2026-10-25 起已在 29 上实测**：Phase 0、#2253、单会话 Phase（#1536、CFG-PT）的结果在 `reports/`，是本机配对筛查结论；其余 PR 的性能数字仍来自对应 PR 的作者/社区机器，未在本机验证。

脚本的本地验证覆盖CPU逻辑、真实loopback HTTP/SSE、统计拒绝条件、配置隔离、可信Java参考断言等；不代表CUDA/Strata依赖集成已通过。tokenizer使用已经核对的固定源码API，但目标机的pack、服务端额外渲染配置和依赖仍需runtime probe校验。脚本故意fail closed。

main更新很快，冻结HEAD已经不是release。PR的GitHub mergeable状态只是检索时信息，不能代替重新构建。#3322的服务支持需要差量工程；其专用drafter切换适配器尚待执行AI在该任务中实现。通用runner不会擅自下载模型或绕过MTP冻结规则。

`auto`只有在用户已有外部AI包装器与正确本地配置时才可从准备到测试连续执行；它本身不包含LLM、不申请API key、不规避工具权限。无AI包装器会生成可读TASK并停止。完整文档包的作用正是让执行AI完成这些开发步骤，而不是伪装已经完成全部移植。

Java隔离使用Docker，不是完整恶意程序验证平台；对这些纯函数测试已限制OS接口，但不宣称能防御宿主内核漏洞。不要在有敏感凭据的高权限开发账号中执行不可信代码。

原生Windows GPU进程/内存适配未实现。PowerShell入口不意味着所有live功能已支持Windows。WSL2的PID视图和内存/cgroup差异可能触发阻断，不能删除审计绕过。

统计报告的通用判定是工程筛选，不提供生产自动发布。真实Pi工作流、项目规模、Java测试量、客户端timeout和compaction策略必须另行验证。对#2822的延迟保证也不能推广到不可抢占的长Prefill。

`docs/02_ENVIRONMENT.md` 中 29 号机的事实（2026-10-23 修订）来自对生产配置、启动日志和 10-12～10-16 真实流量的只读统计，不是本包在 29 上的运行结果；KV 驻留方式、main 在 CUDA 12.3 上能否编译、约 10% 回复重读的原因、堆保留与 Host KV 缓冲的关系仍未验证。

## 单会话结论的限制（2026-10-26）

- `session_bench` 不模拟 Pi 的 compaction：会话写满即停。PT=0 “约 2 倍轮数”是到上限前的轮数；compaction 之后的质量和速度没有测。
- 没有测带工具调用的 agent 会话，只测了“追加文件 + 提问”和编码链两种形态。
- 质量证据有天花板效应：6 条 8 轮编码链全满分，只能说明“在这个难度下没有掉分”。正式 2pp 非劣在单 4090 上不现实（[统计](05_STATISTICS.md)），需要用户真实 Pi 使用作留出。
- 采样负载下单轮生成长度差异很大，单轮墙钟不可比；每个 arm 只有 1～6 个会话，TTFT 均值的区间较宽，结论按配对筛查口径报告。
- `tools/session/` 的脚本没有接入 schema2 计划和 `COMPLETION.json` 收尾回执，不能产出正式采用门的 PASS。
- `tools/session/run_session.sh` 的 `LAB_PYTHON` 默认值是 29 的 venv 路径，换机器时设置该变量。
- 正式门要求的 restricted time-to-success 分析器和真实 Pi 任务适配器（v2 P00）还没有实现。
