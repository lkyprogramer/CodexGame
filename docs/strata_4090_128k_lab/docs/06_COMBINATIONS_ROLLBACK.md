# 组合、冲突与回退

所有实验项先独立从A0开发，不能以前一项候选为下一项baseline。单项通过后另建组合worktree。

| 组合 | 初始策略 | 原因 |
|---|---|---|
| 3453 + 1536 | 可在单项通过后组合 | Kernel表与Python编码路径相对独立，仍测质量/吞吐 |
| 3517 + 3584 | 先审计后组合 | 同时改变checkpoint保留与恢复，不能机械合并 |
| 3307 + 3281 | **禁止初始组合** | 都管理MTP/Prefill资源生命周期，存在双重借用/回收风险 |
| 2964 + async/overlap/其他cache模式 | 原PR明确限制 | 不为绕过guard而删除安全判断 |
| 3711 + 3584 | 最后组合 | 状态所有权、旧snapshot donor与释放路径耦合 |
| 2253 + #2962 | 2253 通过后第一个组合 | #2962 在空闲时按下限归还已 park 会话，内部同样先 trim；两者共享门槛读数 |
| 2253 + 3711 | **不初始组合** | 3711 有意保留页面，与 2253 的归还内存方向相反；只在 2253 让内存有界后、带回收上限评估 |
| CFG-IL0 + CFG-EXACT | 各自通过后再测组合 | 都改动 verify 窗口的多 token MMVQ 路径（IL 交错与 B6 跨行复用），收益可能不叠加甚至相抵 |
| 3453 vs CFG-IL0 | CFG-IL0 只作参照 arm | 候选 sm_89 表在 ≥64K 上不得慢于 IL=0；IL=0 已进入公共基线时，#3453 的 off/on 都在其上比较 |
| 2253 vs CFG-MMAP | 互为对照，不叠加评估收益 | 针对同一根因；若二者同时启用，trim 几乎无事可做，结果不能归因 |
| 2822 + 1536/3584 | 后置 | STOP/DONE、原token序列、暂停恢复共同影响正确性 |
| 3322 + MTP | **互斥drafter** | 不能同时持有并使用两套draft状态冒充公平对照 |
| 3322 + 3307/3281 | 不直接组合 | DFlash资源生命周期与MTP完全不同 |
| CFG-CPUSHARE 4096 + CFG-AUTOMAX 16384 | 可同时上（组合未实测） | 作用区间不重叠：前者只改 [3072, 4096) 的 chunk 读法，后者只改超过 8192 的读入的 chunk 数；在 ≤16K 的读入里，AUTO_MAX 让读入不再拆出余数 chunk，4096 门槛只剩单 chunk 读入用得到。两个都是 env，删掉即回退 |
| CFG-KVRES + CFG-AUTOMAX 16384 + CPUSHARE 4096 | 可同时上（已实测读入，已上生产） | KVRES 的追问读入补测就在 AUTOMAX 16384 + CPUSHARE 4096 上做（7～12K 每次 +0.26～0.43 s，3.2K 不变）；专家槽两种情况都是 10290；生产冒烟通过（[DEPLOY-KVRES](../reports/DEPLOY-KVRES-20261026.md)）。与 `--kv-grow` 互斥。回退是拷回 `backup-20261026-kvres/strata-iq3_xxs.json` 并重启 |

## 回退

常规回退：结束**实验拥有的**server，保留日志。29 上生产服务 `openclaw-qwen38-next.service` 当前处于停止状态；是否、何时恢复由用户决定，实验 AI 不自行 `systemctl start`。生产从 0.1.43.1 升到 A0 是用户审批的独立变更，不由实验包执行；回退路径是保留的 0.1.43.1 部署树与 unit 备份，不删除。测试从未改生产配置，不能用`git reset --hard`回退用户仓库。

单项候选可通过完整feature off重启回到A1；如果涉及初始化分配，禁止只改运行中的环境变量。内存错误、图捕获失败或状态污染后必须新进程，不能继续用损坏session跑下一组。

保存：原启动方式/服务管理器、配置hash、exe hash、模型/pack/template/profile身份、环境变量名单、监听端口。不要把API key复制进公开报告。

## 推荐组合路径

所有组合都在 MIG 有结论之后、于 A0 上进行。先做 #2253（同时得到 CFG-MMAP 的对照结论），通过后叠加 #2962。再试3453+1536（若 CFG-EXACT 通过，它已是所有 arm 的公共基线）。根pin问题确有复现再加3517。长Prefill证实受限时在3307与3281中只选净收益更高的一种。#3711 只在 #2253 或 CFG-MMAP 之后、设回收上限时评估；只有加载后 MemAvailable 足够才考虑 3584 及其与 3711 的组合。抢占与DFlash2另开较长验证阶段。最终组合需要重新跑A/A、full、真实Pi留出集，不能把各项增幅相加。
