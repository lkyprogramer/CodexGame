## 问题

在 B2 生产树上加强路由近似，能否让长上下文 decode 快 4% 以上，同时满足两个条件：305 题任务门对精确路由仍非劣（margin 5%），重复迹象不增加？候选有两类：

- 尾部跳过从 rank 7 收紧到 6 或 5；
- 保持 rank 7，再加常驻专家偏置 `STRATA_ROUTE_PRIOR` 0.25 到 1.0。

2026-11-24 用户接受了"会改变输出、但过质量门"的方向。是否采用仍由用户决定。

## 依据（已核实）

- **开关存在**：v0.2.17 的引擎（0.1.63）认 `STRATA_ROUTE_PRIOR`。它给已在卡上的专家的路由 logit 加一个数（DETAILS.md），生产没有启用。
- **上游经验**：
  - 0.2.7 在 13 GiB 及以下的 N 卡上默认设 1.5。RTX 3060 上 story 快 15%、code 快 37%。
  - 0.2.8 收回了这个默认值（#4402）：长 agent 会话里出现重复循环、结果变弱。10 个 agent 任务平均通过 4.5 个，关闭时 5.6 个。设 2.0 时出现复制和代码缺陷。

## 第二阶段：长会话回放测速（停生产约 1.5 小时，每次运行之间恢复生产）

- **负载**：与[长上下文探针](B2_ADAPT_LONG_20261123.md)相同，120 个请求，其中 70 个 ≥32K。`REPLAY.json` 的 sha256 必须是 `f9d36636…`。
- **顺序**：C0a、TS5、P10、TS6、P05、C0b。两次对照夹住候选，两类候选交替。第一阶段没过的候选由 `replay_run` 拒绝，直接跳过。
- **指标**：
  - 主指标：≥32K 请求的引擎 decode tok/s；
  - 次要指标：同一批请求的每窗口 ms 和每窗口 token 数；
  - 重复迹象：`finish=length` 的回复数，以及服务端的重复 token / 重复思考提示数；
  - 同机负载：每次运行期间 docker 容器 CPU 的均值，取自[生产监控](../tools/monitor/README.md)的分钟采样。
- **有效性**：沿用长上下文探针的检查（120 个请求全部成功并对齐、启动参数正确、无守卫）。另加 `env_ok`：运行目录里 `config.json` 的 env 必须等于预登记的 env。

**判定**由冻结的 `approx_verdict` 机械计算：

- **噪声**：AA = |C0a − C0b| / 两者平均，过门线 bar = max(4%, 2×AA)。
- **过门**：两条同时满足——
  - 增益 = 候选 ≥32K decode tok/s ÷ 对照平均 − 1，不低于 bar；
  - `finish=length` 和重复提示各自不超过两次对照的最大值 + 1。
- **无效**：任一运行无效，判 INVALID。
- **同机干扰**：任一运行期间 docker 容器 CPU 均值 ≥ 1 核，判 CONTENDED。该运行用 `--rerun` 重跑一次后重新判定。
- **漂移**：相对上一轮对照（b2-adapt-long 的 C0a、C0b）的变化只记录，不参与判定。
- **进入第三阶段**：过门的候选按增益排序。与最快者相差不到 3 个百分点、且 KL 更低的候选排第一。最多两个进入第三阶段。全部不过门则判 NO_GAIN，生产不变。

## 局限

- **KL 是筛查**：KL 尺子固定专家缓存、关闭自适应层，而生产的常驻集合会变，常驻偏置实际作用的专家集合不同。
- **长会话覆盖不全**：回放用固定历史，任务门是单轮编程题。#4402 的问题出现在长 agent 会话里，本轮只能部分覆盖。
- **不测组合**：两类开关共用 CPU 专家这一段，本轮不测组合（例如 TS6 加 P05）。

## 预算与边界

- **停生产**：
  - 第一阶段约 15 分钟；
  - 第二阶段最多 6 次运行，约 1.5 小时；
  - 第三阶段每臂约 2 小时，最多两臂。

  每个阶段结束、每次运行之间都恢复生产。
- **不动的东西**：生产树、引擎、驱动、CUDA、NGINX 都不改，不启用 STAGE_PIN 和 ROUTE_RESIDENT。
