## 问题

在 B2 生产树上，把思考模式的 temperature 从 1.0 降到 0.8 或 0.6（`top_p 0.95`、`top_k 20` 不变），decode 能否快 5% 以上，同时任务质量非劣、没有更多重复或截断？

依据：
- 引擎调参已经穷尽（见 [自适应层](B2_ADAPT_PROBE_20261123.md)、[长上下文](B2_ADAPT_LONG_20261123.md) 和防重复台账）。每窗口耗时与采样无关，但每窗口产出的 token 数取决于草稿接受率，而接受率随采样变化。
- [v0.2.20 报告](../reports/V0220-UPGRADE-GATE-20261123.md)：greedy 让接受率从 0.643 升到 0.775，每窗口 token 数 +32%。greedy 风险太大，本轮只测适度降温。

## 现状（已核实）

- Pi 的 `models.json` 对 `openclaw/Qwen3.8-next` 的思考级别显式发送 `temperature 1.0 / top_p 0.95 / top_k 20`（`off` 级别发 0.7/0.8/20）。
- 服务端的模型卡默认值（`server_parts/http_api.py` 的 `MODEL_CARD_SAMPLING["qwen4exp"]["thinking"]`）也是 1.0/0.95/20，两者都没有 presence penalty。所以 gate 和回放那种不带采样参数的请求，和 Pi 的真实请求用的是同一套采样；今天的对照可以直接当基线。
- 请求里的字段优先于服务端默认值。
  - 实验时：用运行配置的 `sampling` 块（`upgrade_gate.py --sampling`）改服务端默认值。
  - 采用时：改 Pi `models.json` 的 `samplingParams.temperature`，服务端不动。回滚就是改回 1.0。
- 真实 Pi 流量（v0.2.19 报告）≥32K 的接受率是 0.63–0.64，和卡片采样一致。

**指标**

**判定**（由冻结的 `sampling_verdict` 机械计算）

判定：**NO_GAIN**。
- T06 和 T08 的回放增益分别是 +0.8% 和 −0.5%，都远低于 5%。
- 测速、重复迹象和有效性检查都满足，所以没有过门的唯一原因是长会话不提速。第二阶段不跑。

观察：
- 降温确实提高了接受率和每窗口 token 数。短 prompt 上，每窗口 token +15%（T06），但每窗口耗时也增加 7%，净收益约 7%。
- 长 prompt 上，每窗口 token 只多 5%，每窗口耗时也多 4%，GPU-reach 从 9.15 ms 升到 9.40 ms。两者相抵，几乎没有净收益。
- 推断：草稿更有把握时，每个窗口要验证和提交更多 token，单窗口更贵；长上下文下 attention 的份额更大，这部分代价更明显。原因没有单独验证。
- T06 回放总耗时短约 9%，但主要是因为生成 token 少了 13%（输出变短），不是生成变快。这是输出风格的变化，本轮不判定它是好是坏。
- T06 在测速里出现 1 次退化输出：ex:wordy 第一次尝试把 `'0'` 连续重复了 256 次，服务端按 `repeat_stop_tokens` 截断（`finish=length`），这题两次尝试都没过。T08 和所有对照都没有出现。次数正好落在过门允许的上限（1 次），但它说明 0.6 已经开始出现低温重复的风险。

结论（按预登记分支）：采样方向判 **NO_GAIN**。Pi 的 `models.json` 保持 temperature 1.0，生产配置不变。真实 Pi 流量以 ≥32K 为主，降温带不来可观的速度；短 prompt 上 7% 的收益不足以抵消输出变化和重复风险。
