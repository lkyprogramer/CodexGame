# 06 · 循环研究

前提：G2 通过，WP-B（观测）与 WP-E（循环控制）完成。所有实验在 Astral fork 上进行，数据写入 `$LAB/runs/<任务>/<UTC 时间戳>/`，内容包括 trace JSONL、命令、指纹和结论。分析在 4090 主机的 CPU 上做（venv 中的 numpy），不在本地开发机上做。

| ID | 问题 | 方法 | 指标 | 模型 |
|---|---|---|---|---|
| R1 | 遍数对质量的影响 | 遍数取 1–6，在固定语料上测 PPL 与 KLD（对 3 遍）；正式版做同样扫描作对照 | PPL、KLD、贪心序列一致长度、tok/s | A4 varloop，A1 对照 |
| R2 | 每一遍在做什么 | 每遍结束时做 logit lens（output_norm + output），对比相邻两遍残差的余弦相似度与 KL；按 token 类型分组（代码、数字、自然语言） | 每遍对最终分布的 KL 曲线；“难 token”的分布 | A1、A4 |
| R3 | 同一物理层在不同遍之间是否选同一组专家 | 记录各遍的路由 top-8，算同一 token 同一物理层跨遍的 Jaccard，以及权重相关性 | Jaccard 分布；可复用的专家比例 | A1 |
| R4 | 跨遍共享 KV | 选项：全局层只保留最后一遍的 KV；SWA 层各遍共享；对照 prototux 的结论（上下文约 2 倍，但出现重复退化） | KLD、长生成（2K token）的重复率（n-gram 重复）、显存节省 | A1、A4 |
| R5 | 循环控制器的作用 | 统计 gain/forget 的分布；消融：令 gain = 0（切断跨遍消息），或令 forget = 0 | KLD、PPL 的变化 | A1 |
| R6 | 按 token 自适应早停 | 当相邻两遍的 logit lens KL < ε 时停止后续遍（varloop 版允许）；扫描 ε | 质量与速度的 Pareto 曲线；平均遍数 | A4 |
| R7 | 草稿器看的是哪几遍 | DSpark 的 target layers [5,23,41,48] 对应 slot 的特征重要性（逐一置零后看接受长度）；DFlash2 的接受长度对 DSpark（作者报告 4.8–4.97 对 3.5） | 平均接受长度、tok/s | A1 + A3 / A5 |

## 规则

- 每项研究先写假设与判据，再看数据；结论分为“支持 / 不支持 / 不确定”，并注明样本量。
- 改动模型行为的实验（R1、R4、R5、R6）必须带开关，关闭时与 G2 基线逐位一致。
- 发现值得做成功能的结果（例如 R4 可以省显存且不退化），另立 P3/P4 任务，经过 G2 后才能默认开启。
- 参考资料：LoopBridge（S14）的预填/解码拆分；prototux（S15）的 KV 共享；varloop 模型卡（S02）的训练说明。读过之后在研究记录中引用具体段落或 commit。
