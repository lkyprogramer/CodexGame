# 11 · R03：2DSD 的验证目标、接入边界与试验

## 1. 定位与当前状态

R03研究token与循环深度两维投机，使用R02 adapter和05事务合同，依赖以任务DAG为准。**v2状态为 `NOT_RUN`：公开实验分支已有Inkling runner，旧版缺码阻塞已撤销。** 固定 `feat/inkling-dspark@962874f303c3142406ab3eecfae2bb51567815c9` 为新参考；仍须完成资产、Atomic接口、SM89、状态/采样与完整请求资格。[S44；40上游复核](40_upstream_refresh.md)

历史main `SqueezeAILab/2DSD@431aade2f1e8ebc98a31158d53c39e554984a83a` 的registry只有Ouro、Nanbeige、Dory；本章v2改用S44实验分支。新分支包含Inkling参考/批量/静态runner，但没有标准Inkling engine model class，使用batch1定制worker。executor自己管理prefix/tree KV，vLLM主要持有权重；移植时必须适配Atomic状态协议，不能假定与标准vLLM scheduler/paged-KV等价。

## 2. 资产与符号必须冻结

| 资产 | 固定版本与约束 |
|---|---|
| 研究target | `thinkingmachines/TML-d24-varloop-research@657b53ba5da7baefe9ff15dca5cd25f5bd3dbaa2`；这是drafter config指定的训练版本 |
| 研究drafter | `minseo25/2dsd-inkling-2-mini-varloop-dspark-drafter@fe3e545788b84e879f3eb8b8f426aaceb5fb44c5` |
| 初始目标合同 | R=3、per-loop KV、无LoopCD；量化/转换单列实验，不能默换成正式Mini或varloop当前main |

原生MTP是3层、`rnn_hidden`、固定visit；此2DSD drafter是5层、`vanilla`，物理feature层为 `[2,7,12,17,22]`，config中的展开索引为 `[2,31,36,41,46]`。committed token读loop-R特征，in-flight token读对应loop-r特征。ID的计数、norm位置、target embedding/head绑定均须保留；hidden_size相同不足以兼容。`model_type=qwen3`也不表示可按普通Qwen3文本模型使用。[S09]

沿用07：`k`表示提出的候选数，`B`表示target验证位置数。本章另用 `b` 表示上游block_size；HF drafter的b=8包含其anchor协议，不能记成8个接受候选。**上游block_size=1仅关闭额外drafter，仍可进行depth speculation，不是纯AR基线。** [S06]

## 3. 哪一步才允许提交

候选 `x_i` 必须由同分支有效prefix `x_<i` 的**最终loop-R** next-token分布验证，通常取前一位置的readout。拿候选自身位置logits验证自身是off-by-one错误。r1审核、r2 promotion/fork只改变候选的继续计算方式；对外stream、永久KV与工具调用只能消费最终验证后的连续前缀。[S06]

采样接受率与残差公式继承07，但 `q` 必须对应候选的真实生成程序：

| 候选来源 | proposal账本要求 |
|---|---|
| main / 浅loop审核后候选 | 保存审核/重采样后的实际提案律，不能统一填原drafter softmax |
| frozen确定性候选 | 上游相应路径使用one-hot；不得换成p_r1 |
| fork | 保存生成该fork的归一化residual；不得换成p_r2 |

上游按main、frozen、fork顺序验证，每次拒绝后更新剩余target residual。`test_wrong_proposals_are_detected`故意使用错误proposal，可以检出分布偏移。多分支精确性需要完整条件分布推导；仅在每条分支贴一维接受公式不构成证明。[S06]

叠加LoopCD时最终p须为guided-AR的分布；仍验证unguided p就仅是另一种proposal策略。量化、KV或sampler改变时重建model epoch，不继承旧“lossless”结论。

## 4. 接口合同（拟新增，不是上游已有功能）

接入前明确以下字段，并复用05的 `begin_speculation / commit_verified_prefix / discard_uncommitted_suffix`：

- `LoopStateView`：physical_layer、execution_visit、logical_cache_slot、pass/phase、prefix与branch身份；active residual、completed blocks、message/controller状态及有效性。
- `DraftFeatureContract`：target/draft指纹、feature顺序与norm语义、committed/in-flight深度、mask embedding和target head版本。
- `CandidateLedger`：parent、token位置、role、proposal种类/分布、生成事件、已完成深度；概率tensor在验证前保持有效。
- `Readout`：早深度readout若需要coda，使用分支私有或只读状态，不能污染最终coda KV/conv。
- `StateTxn`：覆盖全部pass的KV/conv、滑窗被覆盖槽位、feature/Markov状态、sampler/grammar及异步lease；纯scratch可重算但须证明。

RNG采用05的proposal/acceptance/residual/target事件账本。丢弃候选状态不回拨已消费的拒绝/恢复随机数。合法fallback为**同一目标合同**的串行执行；不同R、KV或guidance不得在同一会话悄悄替换。

## 5. 分步试验与交付

### 步骤A：证据与能力门

核验03资产与adapter及40中的S44分支。runner已公开，不再用缺公开代码作为默认阻塞；缺匹配资产、实际Atomic适配或SM89环境时记录具体BLOCKED。正式Mini的2DSD默认drafter仍为空，不能用varloop资产替代。可先用公开支持的Ouro验证算法，结果不外推到Inkling。

### 步骤B：独立算法载体

在隔离checkout运行上游CPU scheduler/sampling测试，至少覆盖stage1/2a/2b、b=1/4、确定性/采样、promotion/frozen/fork、错误proposal负例。以下是已核对存在的上游入口，**本包未执行**：

~~~bash
git clone https://github.com/SqueezeAILab/2DSD.git research-2dsd
cd research-2dsd
git checkout --detach 962874f303c3142406ab3eecfae2bb51567815c9
uv sync --locked --no-editable
source .venv/bin/activate
python -m pytest tests/vllm/test_drafter_finalized_sampling.py tests/vllm/test_drafter_finalized_scheduler.py -q
~~~

该环境锁Python3.12、torch2.11.0、transformers5.17.0、vLLM0.26.0+2dsd，并要求CUDA13兼容驱动；不能覆盖Atomic环境或因此自动升级主机。上游测试GPU列表不包含4090，构建成功和本机收益仍待验证。[S06]

### 步骤C：建立同目标oracle

用R02 adapter建立R3、per-loop、固定数值配置的串行oracle；先对齐prefill和后续decode logits/state。明确AR执行定义，禁止把b=1当AR。检查128/1024/2048输入、SWA边界前后以及多token验证；正确性通过后再扩大到业务上下文。

### 步骤D：逐级接入

先depth-only，再加入5层drafter，最后promotion/fork；一次只改变一个阶段。R3初始按卡的b=8、r1=1、r2=2，但仍须证明实际k/B映射。故意让每个候选位置拒绝，覆盖全接受、EOS、cancel、滑窗覆盖；恢复后再串行生成至少64token，比较oracle状态与输出。

### 步骤E：采样与性能

先small-vocab枚举质量守恒与条件转移，再多prefix频数/PIT回归；加入已知错误版本证明测试有检错能力。固定seed仅要求同执行过程可重放，不要求不同spec算法逐token相同。top-p排序与processor顺序应与reference一致。

最终必测同target、同runner的AR与2DSD。只有存在并通过资产/feature/head校验的、匹配该研究target revision与R的native drafter时，才加入同目标原生DSpark对照；否则该对照标BLOCKED/不适用，不用正式Mini成对资产充数。正式Mini可以另作业务模型对照，但不是同目标算法加速比。记录TTFT、任务时间、接受前缀/emit、branch峰值、draft/feature内存、H2D与恢复成本。原始与重复过滤结果分开，验收用01/13/14规则。

## 6. 共享KV是另一个变量

| policy | 本章处理 |
|---|---|
| per-loop | Inkling drafter卡明确使用；R03初始配置 |
| 2DSD lagged `shared_last` | 历史 `j<=t-W` 读final-loop KV，近处仍逐loop；不是HF `last_loop` 的别名 |
| HF PR `last_loop` [S11] | 由R01单独验证；与2DSD的组合只进入R05 |

2DSD源码对lag策略要求 `R*b<=W`，W包括query自身，确保在途span仍有自身loop KV；普通spec另有 `1+num_speculative_tokens<=W`。历史main通用路径要求单GPU、BF16 activation/KV、V1 runner、关闭prefix caching/chunked prefill，只支持Ouro/Nanbeige/Dory。新Inkling分支是另外的定制worker/plane路径，不能继承通用路径的完整服务资格；GraphRunner即使lagged读取共享也仍分配full-plane KV，必须测实际bytes。Ouro/Nanbeige用适配后的共享KV target，其精确性是相对**该target**，不是原始权重。[S06]

不得直接把PR开关、W=64蒸馏权重与Inkling drafter拼在一起。R05前必须定义多tokenchunk、共享历史提交水位、conv隔离和最终readout，否则为 `BLOCKED`。

## 7. 验收与停止

通过要求：资产/feature匹配；greedy/state通过13；sampling有推导、枚举与回归证据；资源合格；业务收益满足01。模型卡的H100 NVL吞吐及跨engine准确率差异只用于提出假设，不是4090保证。[S08]

- 缺runner、目标或实际proposal：`BLOCKED`，继续可独立完成的载体测试。
- 非法stream、分布/状态错误、近窗恢复错误、OOM/lease泄漏：`FAIL`并隔离候选。
- 约1.01GiB BF16 drafter权重加buffers挤出target、PCIe Gen3搬运抵消收益，或业务收益未达门槛：`NO_BENEFIT`；最多两轮有profiler证据的修正。

R=4/5循环实验移交R02/R05，不能把模型卡报告当作对正式Mini改R的授权。2DSD相对AR的倍率也不能再乘原生MTP倍率。
