# 01 · 产品目标、约束与决策

## 1. 目标

把 Inkling 培养为这台 4090 上可承担 Pi / Java 8 Coding Agent 的下一代主力模型，并以 Atomic Engine 为长期可维护底座。成功的衡量是：在质量、工具协议、长上下文与完整状态恢复通过后，减少真实任务完成时间，或用可解释的容量收益支持原来不能可靠完成的任务。

此处“下一代主力”是工程目标。正式切换仍取决于验收，不能通过预先宣布胜过当前 Strata/NInfer 来替代比较。

## 2. 已知环境与待现场采集项

| 项 | 规划依据 | 处理方式 |
|---|---|---|
| GPU | 单 RTX 4090，24 GB，SM89 | T00读取实际总/空闲显存、驱动和占用 |
| CPU / RAM | Xeon Silver 4216，64 GB DDR4 | 采集NUMA、线程、内存可用量；不假设满带宽 |
| PCIe | 历史环境为Gen3 | 在负载下确认实际宽度/代际及H2D带宽 |
| 磁盘 | 历史约600 GB SSD | 型号、余量、文件系统、实测随机/顺序I/O均未确认 |
| OS / CUDA | 历史有Debian12、CUDA12.3/12.4记录 | 不选一个当现状；T00记录driver、nvcc、runtime三者 |
| 当前服务 | NInfer定制分支、Strata；历史配置131072 context、INT8 KV、kv-resident32768、parallel1、Vision Off | 只作为业务/回退依据，不把参数照搬 |
| 业务 | Pi / Java8、跨文件代码、工具调用、长会话；可有2–3子代理 | 起步GPU并发1，子代理排队；并发2另做资格测试 |

以上硬件与业务来自既有会话约束，不代表本次现场检查。实际库存变化写入机器清单，不修改历史证据。

## 3. 采用的路线及备选比较

| 路线 | 选择 | 理由与代价 |
|---|---|---|
| Atomic普通CUDA全驻留 + 固定Mini + 原生DSpark | **主线首选** | 尽量避免PCIe Gen3搬运，先证明低风险系统收益；仍需验证通用CUDA支持与资源峰值 |
| Atomic离散预算 + loop-aware专家驻留/分层 | **容量证据触发** | 复用Atomic预算/lease思路，解决高量化或长上下文容量压力；需要新增Inkling CUDA资格、状态与回滚支持 |
| varloop + 2DSD / LoopCD / shared-KV | **独立研究线** | 能探索额外效率/质量，但模型、分布或实现前提不同，不参与初始生产承诺 |
| 直接整体移植squid5090或改用另一底座 | 不采用 | 不符合用户选定Atomic底座；Blackwell实现与4090不同，只借鉴可移植机制 |

这些是本方案的工程决策，可随证据修订。未经过本机测量的速度和资源预估不得写成产品规格。

## 4. 能力分层

- **C0：可重现。** 固定源、模型、模板、命令和硬件记录；能重跑失败。
- **C1：固定Mini可用。** 4K/16K串行CUDA、正确文本/工具协议、稳定状态。
- **C2：高效主线。** DSpark与系统优化在同模型同量化下有端到端增益，能自动退回串行。
- **C3：长上下文主线。** 64K与128K按真实输入、输出预算和状态恢复验收。
- **C4：研究增强。** last-loop、varloop、2DSD、LoopCD逐项报告质量与成本。
- **C5：服务候选。** Java/Pi任务、排队、故障、长时间运行和回退全部通过。

200K/262K作为扩展能力表中的独立行。官方更大的模型上下文声明，不等于这台机器的容量、速度和任务质量证明。若既有业务确实依赖200K以上，只有通过对应行才允许替代那部分流量。

## 5. 成功标准

所有门槛都是**本方案的验收策略，不是论文结论或硬件预测**。

1. 系统优化必须在同一个目标分布下先通过对应正确性门；质量变化单独评估。
2. 单项可保留的优化：主要业务分层加权的请求耗时中位数至少降低5%，配对bootstrap的95%区间支持正收益，关键分层p95退化不超过5%。小于5%可作为维护成本很低的局部改进，但不独立成为版本升级理由。
3. 主力迁移的性能目标：真实任务耗时中位数至少降低10%，95%区间支持正收益；质量非劣、关键工具协议无回归。若新模型胜在质量/容量而速度未达标，必须明确作为不同产品取舍，不能声称完成性能迁移。
4. 容量功能可以凭新增长上下文能力晋级，不强求短上下文变快；要注明时延代价，并经过容量专属验收。
5. 各能力行均有固定版本、可重放输入、资源峰值、状态恢复和失败计数。禁止把某一行PASS外推成全矩阵PASS。

## 6. 不允许的捷径

不减少固定Mini循环数来冒充同模型加速；不把量化变更隐藏在kernel对比中；不只测4K+64输出；不以100%草稿接受率的重复语料代表Agent；不把引擎预算当整机RSS；不把逻辑文件读取当物理SSD流量；不把多个公开加速倍数相乘；不自动重启已有no-benefit路线。

## 8. 本包完成与产品完成的区别

本包完成需要：文件齐全、内部引用有效、任务依赖无环、命令分类明确、辅助工具自检通过、重要来源可追溯、独立审查完成。产品完成需要另外在目标4090执行T00–T12并满足相关研究/发布门。两者状态分别记录。
