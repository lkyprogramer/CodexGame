# 02 · Nabo 的启发：把 kernel 调优改成可证伪的证据链

## 1. 文章实际适用范围

[原文](https://www.nabo.dev/blogs/kernel-primer) 的案例主要来自 H200、JAX/Pallas 与 RL/批处理。值得借鉴的是诊断方法：先定位端到端成本，再检查生成代码和硬件计数，最后用无 profiler 的完整任务验证。作者也给出局部提速未等比例转化为阶段收益、单独 kernel 破坏已有融合的反例。

这不是 Strata、SM89 或 128K 单流 MoE 的跑分；也不是一套可以直接装上的调优平台。本文以下是针对你环境的独立工程设计，不是原文结果的复述。

## 2. 六个问题，替代“挑最慢 kernel 改写”

| 要回答的问题 | 需要的证据 | 本增补落点 |
|---|---|---|
| 源码调用最后变成什么？ | 源 SHA、编译配置、已加载模块身份、PTX/SASS | 04/05章 |
| 某 shape 真正在这轮执行了吗？ | dispatch、graph generation/replay 与请求映射 | 原包 O3 + 新路径附件 |
| 时间长是多搬数据还是推进慢？ | 同 scope 的读写 bytes、duration、缓存与replay设置 | 定向 counter 协议 |
| 简化索引是否真的缩短依赖？ | 数值相同、生成代码差量、寄存器/动态计数 | 单一机制证据卡 |
| 融合是否减少全阶段成本？ | stage topology、临时buffer、占用与并行变化 | 完成路径与资源合同 |
| kernel 变快是否任务更快？ | 原冻结统计与任务质量、observer-off结果 | 原包 O5/O6，不新建裁判 |

原文中页索引表达式、route grouping、精度转换链可启发“检查哪里”，但不是本机立项理由。尤其单流 MTP4 的 nt 很小，不能套用大批量 route-sort 的成本结构；训练反向和多卡通信则在本次范围外。

## 3. 三层模型，不把 roofline 当实测

先记录实际张量形状、packed量化表示、scale/zero-point、padding、temporary和访存层级。有效载荷字节与 DRAM 实际传输字节分开。

在固定数据量、匹配精度和资源假设下：

~~~text
kernel_floor = max(required_DRAM_bytes / admissible_DRAM_peak,
                   required_operations / matching_compute_peak)
~~~

这是理想化的下界模型。不能用实测可持续带宽当硬件物理上限后宣称严格 lower bound；应另标 empirical_reference。INT unpack、地址计算、cache hit、CPU专家、PCIe和同步等未纳入的成本写入 assumptions/missing，不默认为0。

然后才把该 kernel 的“最好可能时间”送入原包完成依赖模型，重算选择的 sink。没有完整依赖、不可变调度证明或可比工作量时，结果只是条件情景，不是净收益上界。原包 L0–L4、4%门槛不变。

## 4. 访存问题要分层排查

- 预期字节少，计数器实际字节多：检查重复读取、写回中间结果、非合并访问、padding/量化元数据；但 cache 层之间不能混算。
- 实际字节近似不变，耗时更长：检查依赖链、等待、并行度、寄存器、共享内存、访问发出能力；低DRAM利用率不自动证明算力不足。
- 比较两种实现：同步记录 SASS、动态指令指标、bytes、持续时间、资源占用与图拓扑，避免只看一个 stall 百分比。
- 静态 STACK/LOCAL 非零只是编译资源现象；不能直接称为动态spill流量，更不能按字节乘时间推算收益。
- 更高occupancy也不是目标本身；它可能与ILP、tile重用、寄存器溢出、其他kernel并行相互制约。

## 5. 4090 特化边界

[NVIDIA Ada 指南](https://docs.nvidia.com/cuda/ada-tuning-guide/index.html)给出的 SM89 上限包括每SM48 warps、64K个32位寄存器、最多24 blocks、100KB共享内存；不能使用 H200 的64-warps分母计算4090 occupancy。产品显存带宽和可用L2还应由实际SKU/工具报告绑定，不把完整AD102规格当作所有4090实际值。

RTX4090 使用 GDDR6X，而非 HBM；文档与字段用 dram_bytes 表示设备全局显存流量。Hopper TMA/WGMMA、Blackwell HES不属于SM89；“有FP8”也不证明当前量化KV/权重路径会执行某个FP8 Tensor Core指令。

**第一批应做的是证据与工具资格，不是FP8转换、route分组、索引改写的参数搜索。** 编译审计发现的新现象可以登记，但旧F02等是否允许重开仍由独立 premise_delta 审查决定。

## 6. 对探索节奏的实际改变

每次只允许一个已获授权的活跃优化候选。顺序为：已有证据审查 → 机制假设与上界 → 最小负例 → 离线代码/产物审计 → 若另外获准才做有界诊断 → 原判据确认或关闭。失败保存一张说明卡，不保留无法解释的候选堆栈。

本章不提供新的GPU预算；正式微基准和端到端测试仍走原lab，而不是创建一套“自动调kernel”服务。
