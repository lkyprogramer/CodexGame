## 实现与保留

固定 U11 `4d3366e5b9a959627a6db1f0eb36932be0482def`，仅取 U10 `94cdb5a975e514935ed4be214ee7f776a8683635` 到 U11 的增量，接到完整 P1 已审内容上。接入多 prefill、完成后 lane fence、独立 export stream/pinned ring、后台 image 导出和直接 linear segment 序列化；cache identity、许可/commit、Target sampling 和 codec 不改。

真实原始 merge stages 和三方内容冲突均保留。唯一内容冲突位于 fail_round：保留 P1 的原轮次成员清理，不清理健康 prefill 或 queued 请求。P1 的执行锁内 RoundFault 恢复、fatal 清理锁、重复 guard、schema20 下 version1 prepare_detail、Responses 失败终态均保留。

集成评审后修复：

- 入队先完成 map/parent/新队列节点分配，再提交 reader 和 sequence，最后合并旧 job。失败不会遗留永久 pending 或删除仍可执行的前驱；不产生无 job 的 session sequence。
- 同一 lane 复用、reset、restore、erase 与驱逐等待真实 host reader 释放。队列停止不提前释放源状态；现有 publication worker 排空后再销毁 Program，没有新增 worker 或缓存框架。
- Publication 构造、parent 复制及 boundary/session 大 image 复制纳入异常边界，记录失败；不会因这些复制异常直接逃出 noexcept worker。失败 boundary 仍允许 session 发布继续。
- 将旧 native 诊断 hook 适配多 prefill，保留 A decode/B prefill/C pending 身份断言。只重新编译，没有重跑旧 native 场景。
- 增加 export-only interval 日志回归和离线归一工具。保留六项 prepare_detail；缺失、负值未知、无效数字输出 null+原因，真实零值保留。publish 语义默认未知，须从固定 producer 身份明确声明 `p1-sync` 或 `p2-async`，不能混用同名字段。

归一工具不把全局 export work 平摊给请求。请求级 export 秒数目前仍为 unavailable；全局计数及同步 fence/enqueue 成本不等于 GPU 完成、持久化完成或完整任务 wall。
