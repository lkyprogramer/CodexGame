# 给后续执行 AI 的启动任务

这是任务说明，不是系统指令、服务启动器或硬件授权。用户实际授权、仓库最新 AGENTS 与工作区状态优先。

## 建议直接交付的第一轮范围

> 基于当前 CodexGame:4090-report，读取本包 README、AGENTS、docs/00–10、18–23及来源锁。先核当前tree/dirty与保护对象，完成P0事实与复用映射；在允许的本地开发范围做P1适配和CPU夹具。P2.0先读取当前身份的有效L0原件，回答现成监控哪些已足够、哪些决策字段仍缺。不运行GPU、不启停服务、不更新驱动/CUDA、不下载权重。若缺原件，交一份有限L0采集申请而不是先写全量hooks。后续每个hook必须对应一个已证明缺失的决策字段。旧失败保留，Phase串行、独立review，交付下一项唯一允许动作。

## 首轮必须交出的五件事

1. **SOURCE_BINDING**：用户tree、最新稳定Strata、tag/main delta、实际binary/build未知项。
2. **REUSE_MAP**：真实存在的runner/http/P01B/合同/统计工具；计划文件与已实现文件分开，引用具体路径。
3. **METRICS_COVERAGE**：每个决策问题→现成字段→scope/单位/时钟→缺口；不以代理指标充当物理状态。
4. **IMPLEMENTATION_RECEIPT**：实际修改文件、失败fixture→实现→回归、独立review与NOT_RUN项目；不把本文档原文当实施回执。
5. **NEXT_ALLOWED_ACTION**：L0已够则报告并停；需采集则给精确轨迹/次数/资源/数据权限/清理/截止；字段不足且证据成立才列最小hook。

## 后续有限采集申请模板

| 要素 | 需要明确的值 |
|---|---|
| 问题 | 一个可证伪决策，不是“尽可能多收数据” |
| 身份 | source/build/binary/model/KV/template/sampler/draft及实生效route |
| 轨迹 | W02→W03→W04或一组必要CASE；总窗与完整token计数 |
| 权限 | 研究机器/实例/端口、允许读取和保存的内容、原始token是否获准 |
| 预算 | 新开引擎、所有请求含失败/prime、GPU时长，各自上限 |
| 终止 | 单调execution/hard deadline、预留cleanup grace、实验owner验证 |
| 判断 | 预登记统计单位/方法、required cases/gold/绝对质量门或明确诊断范围 |
| 缺口 | 哪些未知会使当前结果止于INSUFFICIENT |

默认请求/启动/GPU预算为0；`experiment_spec.json`、`run_evidence.json`、`decision.json`、`budget_ledger.json`是待绑定映射草案，不是可以原样传给旧validator的实例。不创建第二套编排服务。P3-L2没有同构建可比off原件就不能声明observer无扰动。C01没有合法W09完整token原件就不能“用SSE推断”。
