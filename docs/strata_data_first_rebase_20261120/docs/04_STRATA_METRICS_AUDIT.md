# Strata 0.2.16 / Engine 0.1.62：4090 长上下文观测审计（2026-11-20，北京时间）

**结论：沿用 Strata 的现有监控，不并造平台；补一个默认关闭、可归因、可关闭的本地实验记录。** `/metrics` 和 `/v1/telemetry` 已能回答「服务是否忙、读/写多少、批在几号槽、显卡大致在做什么」。它们不能回答「这个 agent turn 的 15 秒到底在哪一层队列、只复用逻辑前缀还是真的省了搬运、哪个 window 的哪个等待在关键路径、为何相同 acceptance 但端到端更慢」。先把这几段接起来，再决定是否开性能分支。本文是源代码审计，没有运行用户机器、打补丁或测吞吐。

### Prometheus 名字、类型、单位、label（均为当前 tag）

`logs --follow`初次调用`activity_delta(snapshot,None,None)`，从seq 1考虑保留段，长运行服务可能先报告**观测开始前**的历史gap。collector先记录初始`(instance_id,last_seq)`与retention边界：不让旧gap否定之后完整窗口，也不能忽略锚点之后的丢失。跨锚点的请求无完整早期证据仍不得强行归因。P1负例同时覆盖历史gap、当前gap、实例重置。

**`/metrics` negotiated**，所有样本 `model_name`；hist 的 `_bucket` 加 `le`，`live_state`/`live_slots` 加 `state`，GPU family 加 `gpu`（index）。`vllm:` 以下是**兼容命名，不是等价语义承诺**：

- gauges：`vllm:num_requests_running`, `vllm:num_requests_waiting` 为数量（后者 `queued+waiting`）；`vllm:kv_cache_usage_perc` 是 0–1 的 **busy request 可见 token/context 比例**，不等于 KV VRAM/page/allocator 使用量。
- counters：`vllm:prompt_tokens_total`, `vllm:generation_tokens_total`, `vllm:request_success_total`（走归档的 finished，不保证每条 API 成功，取消也可能入账）、`vllm:prefix_cache_queries_total`（prompt token 数的代理量）、`vllm:prefix_cache_hits_total`（reused token）、`vllm:spec_decode_num_draft_tokens_total`, `vllm:spec_decode_num_accepted_tokens_total`（跨当前 `DONE` 计数，不保证 MTP-only，亦非每角色），`vllm:num_preemptions_total` **硬编码 0**（不能证明没有 wait/让路/缓存重读/落盘）。
- histograms（秒）：`vllm:time_to_first_token_seconds`, `vllm:inter_token_latency_seconds`, `vllm:e2e_request_latency_seconds`；桶界 `.001,.005,.01,.02,.04,.06,.08,.1,.25,.5,.75,1,2.5,5,7.5,10,20,40,80,160,640,2560,+Inf`。归档阶段观测；ITL 实际把`decode_s/(output−1)`放入同一个桶 `output−1` 次，不是观测后处理/SSE 每 token gap，不能算真实 p95 尾延迟；TTFT/E2E 起点是 server busy 时 `started=time.time()`，大致在 load 后、未必在 native slot admission 后，两者均不等价于 ingress、client TTFT。
- `strata:` gauges：`live_state{state=unloaded|idle|reading|generating}` one-hot；`live_slots{state=idle|reading|generating}` 个数，slot list 空则不出；`live_tok_s`, `live_prefill_tok_s_mean`, `last_decode_tok_s` 为 tokens/s，`live_prompt_read`, `engine_max_context` 为 tokens，`last_hit_rate` 为 0–1 末次请求比率；`gpu_util` 百分数，`gpu_mem_used_bytes`, `gpu_mem_total_bytes`, `ram_used_bytes`, `ram_total_bytes` bytes、`gpu_temp_celsius` °C、`gpu_power_watts` W、`cpu` 百分数。缺数值的可选样本不出；三个 live rate/read 显式 fallback 0。Counters：`totals_prompt_seconds_total`,`totals_decode_seconds_total`，从 ms 除以 1000、不能当 GPU active 时间。

**`/metrics/prometheus` legacy**：无 model/replica label。`llamacpp:` counters `prompt_tokens_total`（**fresh = prompt−reused**，与 `vllm:` 不同）、`prompt_tokens_cached_total`, `prompt_seconds_total`, `tokens_predicted_total`, `tokens_predicted_seconds_total`；gauges `prompt_tokens_seconds`, `predicted_tokens_seconds` (tok/s, scrape-window), `requests_processing`, `requests_deferred` (#)。`strata:` counters `requests_total`, `drafts_offered_total`, `drafts_accepted_total`, `tool_calls_unread_total`, `tool_markup_retries_total`, `tool_args_repaired_total`, `conversation_cache_parks_total`, `conversation_cache_restores_total`, `conversation_cache_evictions_total`, `conversation_cache_refused_total{reason}`；gauges `model_loaded` (0/1), `conversation_cache_parked` (#)。不得同时 scrape 两个端点后无视口径混合。Bot/推断无须改名，实验走 separate feature-gated evidence。

### 采样、重启与归因

- `Telemetry` [L1607–1758](https://github.com/Niko1221/Strata/blob/64524fb9fc82222ddce554c0643b64f056ec8366/terminal/serve/telemetry.py#L1607-L1758) host thread sample 后 wait 1s，并非严格 1 Hz；最近 60 的 history 是数组，不是各点独立的时间戳。NVIDIA 原生 NVML，GPU 热功耗/total/used/PCIe width/gen/rx/tx；单卡使用对应探头，多卡时聚合字段按 mem/power/PCIe throughput 求和、util 取均值、temp 取最大，链路 gen/width 留第一张（`gpus[]` 单独给各卡）；CPU/RAM/disk I/O 多为**系统级**（`psutil.disk_io_counters` 相邻 wallclock 差分 / 2^20，MiB/s，不是 engine 或专家 SSD），底层设备采样更新时间有别于 GET。采样异常保留上次 now，不能从 GET `time` 推知硬件 datapoint 新鲜。GPU `gpu_pcie_rx_mb/tx_mb` 为 NVML KB/s 除以 1024（MiB/s 窗口读数），不是 request byte 记账。Prometheus 无 `gpus[]` 时可能用 synthetic `gpu="0"` 兼容单探头，不能把 0 当系统卡的物理索引；用配置/`/v1/telemetry` 映射。Live tok/s `server_parts/base.py` L231–234 + `server.py` L4646–4680：2 秒窗口、至少 250ms、32 个观测点，fallback 自首 token mean，并发加数是多个请求的速率，而非同一严格窗口的观测。
- 终端 batch `engine/include/strata/core/batch_telemetry.hpp` L12–47、L49–98，`generate.cpp` L15906–15924/L17242–17257，`server.py` L685–691/L1007–1016/L6751–6800。默认关 `STRATA_BATCH_TELEMETRY=1`（配置 `batch_telemetry`）。`BSTAT windows processed_rows active_rows elapsed_ms`：完成 decode windows，分子包含 padding/MTP 等，不是输出 token；从最早 window 起点到最后结束，一秒或 all-idle partial 后重置。`PSTAT n_stages elapsed_us in_flight_us…`：每 stage launch→host completion poll，包含调度/轮询延时，并非 SM 利用；仅适用多 stage。Python 用 `time.monotonic()` 记 **receipt age**，Overview 超 5 秒弃用，详细页可显示 stale。子 replica 不同取样窗口保留分别测量；不跨 replica 求均值/相加，也不把第一个 child 的 INFO 当所有。`replicas.py` L373–485/L576–623：`last` thread-local，`info` 以首 child 为基；split handover 与 replica mode 也不应混用。
- `Service` [`server.py` L5323–5417、L5461–5470、L5729–5782`](https://github.com/Niko1221/Strata/blob/64524fb9fc82222ddce554c0643b64f056ec8366/terminal/serve/server.py#L5323-L5417)：terminal id 在 generation 入口生成；`queued_at`,`admitted_at`, activity `at` 和 `started` 都用 wallclock。非并行 `admitted` 是 FIFO acquired、在 possibly load 前；并行是进 waiting registry、在真正 native control/slot 仲裁前。因此 `queued→admitted` 的两种含义不同。`reading` 回调可辅助区分但重入/continuation 会聚合，「客户端首可见文字」在 parser/SSE 之后，`first_engine_token_s` 是 `perf_counter` 从 generation queue entry 到**首 engine token**，不是上游 harness scheduling、HTTP TTFT，也不保证是 content token 或 tool 已可解析。终端目录没有 harness parent/child/session ownership 或 ingress 时钟。老合同中的 `server_wait - prefill` 不是一个可以命名为 queue 或 GPU idle 的差值。
- 主 `Service.history` 最多 500，`totals` 和 hist 是 Python 实例 lifetime（engine 重启不必归零；以 `instance.id` 跟踪服务重启）；`CONV_CACHE` 是引擎 log run 的增量线路，独立 reset。`/metrics` 历史 p95 与 after-warm-up 同组请求分位数不同，且汇总在 request finish，不可对 KV/工具重试跨代作无条件拼接。SSE client 只以本地单调时钟衡量首次 body/frame/content/工具结构化完成，保留空/取消/错误样本结果标签。

## 4090 的 profiler 能力与边界

| 能力 | RTX 4090 / Ada `sm_89` | 采集原则 |
|---|---|---|
| CUDA events / NVML counters | 可用；前者流内 elapsed，后者系统采样 | 不能把两个 GPU streams 的 durations 加成 wall time；必要时以 host monotonic anchor 和 dependencies 校准。无同一 clock 或丢事件就只做子窗口解释。 |
| Nsight Systems / CUPTI 软件 activity（runtime/driver/kernel, graph, memcpy）；必要时 Nsight Compute 单 kernel | 按 installed driver/toolkit、OS/WDDM/WSL 权限做 capability probe；不是「4090 不支持 CUPTI」 | 默认先少量单请求 graph/window 级；只有在不知道 critical exposure 时开 node trace。保留无 profiler 的 paired baseline，显式记录丢失/限制和 graph capture vs launch correlation；不要同跑 profiler/subscriber 以致互相影响。Nsight Compute replay 样本只回答具体 kernel 瓶颈，不用于端到端 A/B。 |
| CUPTI HES hardware timestamping、Strata PDL | HES **无**（NVIDIA 文档 Blackwell+）；PDL **无**（Strata `pdl.hpp` L27–34 / `verify.cpp` L1418–1432，sm_90+，不能用 `STRATA_EMULATE_CC` 伪造真实资格） | 仅借鉴层级/相关性采集思想，不立 HES/PDL 项目，不把 Hopper/Blackwell 的 overlap 投影到 Ada。 |

参考：[NVIDIA CUPTI Activity API](https://docs.nvidia.com/cupti/api/group__CUPTI__ACTIVITY__API.html)、[CUDA Graph tracing/HES](https://docs.nvidia.com/cupti/main/main.html#hardware-event-system-hes)、[Strata PDL gate](https://github.com/Niko1221/Strata/blob/64524fb9fc82222ddce554c0643b64f056ec8366/engine/include/strata/kernels/pdl.hpp#L27-L34)。仓库所审 CMake/端点及 CUDA 主链没有生产 CUPTI/HES endpoint；旧 #5524 是 V100/WDDM/nsys node trace converter 失败，不在同机同版本，提示保留工具兼容 fallback，不证明 Ada 不能抓图。

## P1 产出判定

| 结论 | 只靠原生即可说 | 原生数据仍不能说 |
|---|---|---|
| 需求/健康 | 什么时候出现活跃、入口拒绝、生成数量、整体速率掉了、硬件靠近满载；窗口样本是否过期 | 更长的 agent end-to-end 因果；同一个 waiting 包含哪层队列及占用，实际结构化工具准备好是否符合 SLA |
| 快速 triage | 同实例/同源 delta counter、标识 reset、样本覆盖、缓存逻辑 reuse、prefix read 少了 | front queue 与 worker queue 因果，同一会话是否被置换、KV/GDN/draft rehydration 是否在临界路径 |
| 归因/决策 | 某个 profile arm 的现象可以缩小范围；同时增加 archive evidence 能锁二进制 | 未受扰动的单路径净收益、kernel 百分比能回收多少端到端时间、真实 ITL 尾分布；这些先过 06 的 P2/P3 才能进入 P4/P5 |

带窗口计数的 derived rate 必须采用同 clock、单位、实例/engine gen 和 window 的观测；处理 reset 或负值用 unknown/no-sample，不取绝对值、不补 0。服务器的 finished counter 或固定为 0 的 preemptions counter 不能替代真实客户端有效答复、缓存复用和队列延迟。本审计无新 telemetry 后端、无运行服务留痕、无真实 GPU profile；所有 hook 为计划。
