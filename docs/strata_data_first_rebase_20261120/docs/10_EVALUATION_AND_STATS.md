# 10｜比较、统计与收益资格

## 1. 三种结论不能互换

1. **测量有效**：身份、覆盖、时钟、observer和质量门成立。
2. **有研发空间**：同一真实工作负载中存在可闭合关键路径，最佳可能净省足以超过门槛。
3. **候选有效**：真实实现通过正确性、资源与独立端到端配对。

前两项通过不等于第三项通过；局部kernel提速不等于任务完成更快。新基线无需超过旧版才能完成采集，但若绝对质量不合格不得投入性能候选。

## 2. 主指标与方向

选择并预登记一个主指标：如W04真实append client E2E，或W02 cold read到首可用输出。不要看完结果后换成最好看的 tok/s。

以时间比 `r = candidate_time / control_time` 为主：越小越好。4%时间减少对应r≤0.96；不要把4%时间减少与4%吞吐增加等同。tok/s仅在实际提交token数、质量和停止条件对齐时辅助比较。

成功任务时间、包含失败的总体时间和失败率分列。失败快不能获性能PASS；排队、必要snapshot/下一轮catch-up、cache restore按预登记终点计入。

## 3. A/A 与观察器

固定source/model/config/请求，交错独立进程/运行块，比同实现重复波动。AA定义为预登记场景下配对时间比偏离1的绝对幅度汇总（本合同默认中位绝对偏差；报告同时保留最大值与完整样本）。

- 初筛3对仅判断明显不稳定或开销过大；无需把“全绿3次”当低噪声证明。
- formal candidate时，正式AA估计与候选独立，锁定噪声值，不能用候选结果反算更低阈值。
- 新baseline和observer判定独立于旧P24；不把旧六对的noise永久当当前AA。
- 每次重启成本和warmup请求都进budget；是否进入时间窗口事先冻结。

三对筛选只能用预登记且适用的估计方法，不能调用六对工具冒充95%结论；无有效小样本CI则只报描述统计/SCREEN_ONLY。P5正式AA与AB分别登记样本量、启动/请求/时长上限，不能把AA混入六对AB预算或以旧三对筛选替代。

## 4. 正式门继承旧思想，不篡改历史

默认后续候选主时间比 **95%CI上界≤1−max(0.04,2×AA)**，其他预登记关键时间指标CI上界≤1.02；资源与质量独立过门。旧合同另有定义时先保留旧结论，新合同必须显式注明采用哪一版。

复用 `frontier/tools/paired_stats.py` 的六对、12fresh engine及exact bootstrap思路，但输入必须满足该工具真实schema/同输出条件。自然EOS或多任务相关样本不满足时，不为了能运行该工具伪装定长；为新合同增加对应统计路径并以夹具验收。

初筛、三对或上界估算不能产PERF_PASS。正式预算只有一个候选通过P4后才制定，不预跑全场景六对。

P4不存在独立正式AA时，4%仅是确定淘汰的最低门，不能假设噪声为0。达到该最低门的唯一shortlist仍为CONDITIONAL_AWAITING_AA，只可申请P5.0的独立测噪；得到AA并重算完整门之前不批准原型/AB。即使上界跨完整门，也仅是研发资格而非实测收益。

## 5. 统计单位

独立单位是预登记任务/完整trace或fresh engine配对block，不是token、kernel、spec round。一个128K请求产生1000round仍只有一个相关请求样本；不得把1000round拿来做极小CI。

- 多turn与父子任务有组内相关性，以整条trajectory/block重采样。
- 样本权重固定；copy-heavy与non-copy分别报告，再按真实目标分布加权。
- 小样本p95只能是描述性分位数（附n/次序统计），不宣称估计了线上P95。
- 冷读、exact-repeat、append的结果不直接平均；解释哪个场景是主目标。
- 耗时分布不稳定/漂移时保留顺序，ABBA/交错可降低漂移但不会自动消除污染。

## 6. 完成路径资格

新候选先给出可审核的保守与乐观估算，输入必须来自本轮合法数据：

`net_saved_time = removable_critical_time − new_compute − new_transfer − new_launch − replay/catchup − lost_overlap`。

重叠项用依赖图做反事实，不把每项累计时间相减。实际不可识别的项标unknown；不能把unknown当0让净省变正。理想上界仍低于max(4%,2×AA)则NO_HEADROOM，足够高但关键项未知则INSUFFICIENT。

建议优先的决策顺序：任务正确 → 数据完整 → observer可比 → 已有实现是否覆盖 → 独立机制 → 净空间 → 实现复杂度/维护/许可。复杂度不抵消质量失败。

## 7. 质量非劣与绝对质量

复用已有 `tools/quality_gate.py`：配对二元任务、预登记允许退化与置信要求。默认2pp合同下，30个无分歧smoke不足以证明；其零分歧Clopper–Pearson/Bonferroni实现约需要183个独立任务，实际仍以工具和假设为准。

这不是要求P3为采集立即跑183题，而是防止把小规模功能验收叫作质量非劣。P3只给BASELINE_DIAGNOSTIC；正式推广前才按所选业务定义质量预算。旧六个长检索FAIL保持，不换gold；一个候选与坏基线同样坏也不能通过绝对质量门。

绝对门由P0/P5质量manifest确定：必测case与gold哈希、结构/真实工具执行与回执、数值/状态等价、缺题政策、绝对阈值。未定义或必测缺失就INSUFFICIENT，不从相对非劣反推绝对合格，不以加权均分掩盖硬失败。

## 8. 无效样本与终止

- 身份混乱、错PID、超窗、权限/占用冲突、required事件丢失、温度≥85°C、内存低于4096MiB时停止新负载。
- 环境污染样本按预登记规则标INVALID，不事后删除对候选不利的点；保留原件。
- 出现输出/状态不一致，先STOP_CORRECTNESS，不继续性能累样。
- 最大次数/时长耗尽即STOP_BUDGET；当前证据不足则INSUFFICIENT，不能自动续费到显著。
- 每次live开始前绑定单调deadline、清理宽限与实验进程owner；资源硬门或deadline触发时安全取消在途实验，必要时由watchdog终止**本实验拥有的**进程组。清理计入预算；owner失配不能杀进程，更不能碰生产，未能预先保证隔离则不启动。
- 原因只有相关性时写“相关”，不是“根因”。负结果、没空间、上游已覆盖均是有效交付。
