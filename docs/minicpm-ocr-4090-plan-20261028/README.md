## 3. MiniCPM 处理链与共同产物合同

```mermaid
flowchart LR
    A[PDF 或页图] --> B[固定栅格化和方向处理]
    B --> C[CPU PP DocLayoutV3]
    C --> D[裁剪和区域分类]
    D --> E[有界区域队列 最多4]
    E --> F[vLLM BF16 标准解码]
    F --> G[区域响应和错误落盘]
    G --> H[阅读顺序和表格公式组装]
    H --> I[JSON TXT Markdown 图片资源]
    I --> J[金标评分和失败图册]
```

每次运行有唯一 `run_id`。同一源文件不同模式、退化级别、解码器和重复次数有不同 run 目录，不覆盖旧结果。写最终文件采用临时文件加原子改名；失败任务同样保留清单与诊断。

```text
/data/ocr/minicpm-ocr-1.0/
  releases/<release-id>/        # source、patches、build-info、镜像/配置/模型锁
  models/main/                 # 完整 tokenizer、processor、config 与权重
  models/draft/                # DSpark 阶段才准备并启用
  models/PP-DocLayoutV3/
  configs/baseline.yaml
  configs/prompts-all-text.yaml
  corpus/originals/            # 原件只读，不复制进 Git 或镜像层
  corpus/rendered/
  corpus/ground-truth/
  runs/<run-id>/<source-id>/
    manifest.json
    document.json
    document.txt
    document.md
    pages/ crops/ assets/
    requests.jsonl
    failures.jsonl
    metrics.json
  reports/<run-id>/
  current -> releases/<release-id>
```

`document.json` 是完整结构记录：源文件 SHA-256、原始和输出页数、页号、方向/坐标变换、区域 ID/类型/坐标、原始 OCR 文本、后处理文本、阅读顺序、表格/公式、图内文字、裁剪/图片资源路径、识别状态和请求指标。派生 TXT/MD 不能成为唯一证据。

每个区域至少记录 `request_id`、`attempt`、请求与有效采样参数、视觉/文本输入 token（可取得时）、请求/有效输出预算、输出 token、`finish_reason`、服务错误、耗时和原始响应。当前 SDK 没有全部保留这些字段，见第 5 节的必要适配；取得不到的指标写 `UNAVAILABLE`，不能填 0。

完整文字合同包含页眉、页脚、页码、脚注、题号、侧注、图注、图内可见字和表格单元格字。版面中答案留白、横线、坐标线不是待补全的文本；保留其版面信息但不得猜答案。无法辨读处按标注协议保留 uncertain 状态，禁止语言模型“纠正文意”替代忠实识别。

跨页表格默认保持逐页结构并记录续表关系；除非另行实现并验证合并器，不承诺自动恢复为一个跨页 HTML 表格。公式输出 LaTeX、表格输出 HTML；几何图、地图和实验图保留原图及标签文本，不以 OCR 成功宣称恢复了图形语义或解出了题目。

### 4.1 推理服务启动模板

以下模板用于已构建、已经应用适配的环境，**不是当前机器上已执行的命令**。容器只映射 `127.0.0.1:18499`，模型只读挂载。SDK 和区域服务先通过本机受控网络访问，远程验收可使用 SSH 隧道。

```bash
.venv-vllm/bin/vllm serve /models/MiniCPM-OCR-1.0 \
  --served-model-name minicpm-ocr \
  --host 0.0.0.0 --port 18499 \
  --dtype bfloat16 \
  --max-model-len 16384 \
  --max-num-seqs 4 \
  --no-enable-prefix-caching \
  --mm-processor-cache-gb 0 \
  --gpu-memory-utilization 0.65 \
  --max-num-batched-tokens 8192 \
  --limit-mm-per-prompt '{"image":1,"video":0}' \
  --attention-backend FLASH_ATTN \
  --mm-encoder-attn-backend FLASH_ATTN \
  --trust-request-mm-kwargs \
  --mm-processor-kwargs '{"downsample_mode":"4x","max_slice_nums":9}' \
  --default-chat-template-kwargs '{"enable_thinking":false}'
```

只读本机验证端点：`GET /health`、`GET /v1/models`；随后必须调用真实区域识别。不要把健康接口 200 当功能验收。若扩大到跨机访问，应先配置认证和受限入口；密钥通过专用运行时 secret 文件传入，不写本文、仓库或请求日志。

主比较C0采样统一为 `temperature=0`、`top_p=1`、`top_k=-1`、`repetition_penalty=1.0`、`enable_thinking=false`。原先Mini的0.01/0.001/1仅保留为N0原生策略参考，不与Ovis C0混合比较。识别提示词按区域使用 `Text Recognition:`、`Formula Recognition:`、`Table Recognition:`；图表转表单列 `Chart to Table:` 测试，不对所有插图强制套用。

文本输出初始上限 4096、表格 8192、展示公式 2048、行内公式 1024；这些是输出预算而不是上下文长度。SDK的 `prompt_reserve_tokens=8192` 只限制静态输出上限，不能代替真实视觉 prompt token 计算。逐区域验证输入加输出预算不超过16384，并保留512 token余量；超界时在记录真实输入长度后缩小输出预算或分块。遇上下文溢出必须明确记录裁剪/分块/降低预算决策，不能只减预算后把截断结果当成功。

### 4.2 SDK 整页执行合同

必须使用**显式配置文件和受控页面执行器**。当前 quickstart 会覆盖为40960上下文、32 workers、布局重叠；官方多页staged入口还先处理整文件布局，concurrent识别会绕过page_workers。因此无config快捷命令和原生多页parse都不能直接作为C0单页接纳基线。

配置必须冻结：CPU 布局、PP-DocLayoutV3 本地目录、16384 窗口、区域 workers 4、page_workers 1、overlap_layout false、区域采样和输出预算、全标签文本保留、图像块 OCR、结果 JSON/页图/裁剪/图片输出。精确字段、官方 SDK 命令与安装补充见 [deployment-details.md](deployment-details.md)；启动前保存 `show-config` 或等价最终配置解析结果，逐项断言，不能只检查 YAML 文件内容。

先用1页中文、1页英文、1个表格、1个公式验证，再通过受控执行器跑三份原始PDF的全页闭环；其单页SDK子任务使用`run.mode=full`、`input.limit=0`。保存接纳/渲染/布局/区域/终态事件，证明接纳1时上一页终态前没有后页处理；原SDK整文档staged参考另列N0。PDF必须经过图像识别，保存实际图像哈希及请求计数，不回填文本层。

## 6. 可选整页 HTTP 包装层设计

若需要直接提交 PDF 并获取整份结果，计划实现下列最小接口；当前尚无实现。使用 SDK CLI/库完成解析，不重新实现布局或模型推理。

| 接口 | 行为 |
|---|---|
| `POST /v1/documents` | 文件上传，返回 202 与 job_id；校验类型、大小、页数和像素边界 |
| `GET /v1/documents/{job_id}` | 返回 queued/running/succeeded/partial_failed/failed/cancelled 及进度、失败页 |
| `GET /v1/documents/{job_id}/artifacts` | 返回授权范围内的 JSON/TXT/MD/图片清单和校验值 |
| `DELETE /v1/documents/{job_id}` | 取消排队任务；运行任务发取消信号并回收工作进程 |

初始只允许 1 个活动文档任务，等待队列上限 8；第 10 个同时提交的任务返回明确 429 与 Retry-After。每个活动文档内识别最多 4 个区域。vLLM 的 `max_num_seqs=4` 只限制活跃序列，不能代替请求排队/客户端连接数量限制。

建议初始输入边界为 50 MiB/文档、100 页/文档、单页不超过 25MP，支持 PDF/PNG/JPEG；超限明确拒绝或按有记录的规则拆成子任务，不静默截去后续页。批量源文件跑成独立任务。TIFF/多帧图、WebP 若通过预处理支持，需保存转码版本和帧/页映射；未适配时返回明确不支持。

区域超时初值 120 秒、每区域最多 1 次可恢复错误重试、单页 deadline 300 秒、文档 deadline 30 分钟。长文档若业务确需更长时间，执行前固定新边界并单独测；HTTP 上传请求不一直阻塞到解析结束。只重试网络中断、短暂 5xx 等可恢复错误；校验失败、确定性 4xx 和截断不能盲重试。

重启恢复以本地任务状态为依据：已完成产物保留，排队项可恢复；运行中任务明确转为可重试失败或从已校验完成页继续，不默默重跑并双写。不要求本次引入数据库或消息中间件。清理仅限本服务可识别的过期工作目录，不删除原件、金标和验收报告。

## 9. 金标、指标与质量门槛

### 9.1 金标制作

金标以**送入系统的固定像素**为依据。Word/XML/PDF 文本层可辅助誊录，但不能直接复制为无误真源。每页标出完整可见文字、区域类型/坐标/顺序、表格格结构、公式 LaTeX、图中文字、下划线/加点/删除线等样式与文字范围、不可辨读/遮挡范围和关键 token。答案文档仅是它自己页面的OCR输入，标准答案不是题面OCR的GT。

原人工验证路径（不是本轮AI验收的前置条件）：人工先不看模型结果制作GT，第二人复核页面和区域；公式、表格、关键数字/字段、手写难字由两人独立判读后仲裁。本轮按用户授权执行AI原图先验参考与独立验收，明确AI来源、核对范围和UNKNOWN，不宣称human_verified。无论采用哪种参考，每次改动均记录原因与版本，同一版本重算全部候选，禁止仅为一个模型结果改参考。

保留两种任务：自动全页端到端；人工给定正确裁剪的区域识别。前者失败、后者通过，优先定位栅格化/布局/裁剪/顺序/组装；两者均错才进一步看模型。失败归因能解释问题，但不能从端到端分数中扣除失败页。

### 9.2 指标口径

- 文本 CER = `(替换+删除+插入)/GT字符数`；同时输出原始、NFC/约定空白处理后的轻量规范化 CER。保留数字、大小写、标点、单位、上下标、正负号，不做 NFKC 等可能改变语义的折叠。
- 英文额外计算 WER；中文按字符，不能把分词差异误当全部错误。代码另报保留空白的 exact match 与逐 token 关键字段精确率。
- 分别报正文、页眉脚注、题号、图内字和表格字 CER/块召回。统计完全漏块、部分漏字、重复文字和无来源新增文字；不能只报平均相似度。
- 表格报告单元格文字 CER、行列/合并格准确性、完整 TEDS 与只比较结构的 TEDS-Struct（工具实现与版本冻结）。跨页关系单独评估，不把整段拼成普通文本后只算 CER。
- 公式报告规范化 LaTeX exact match、渲染成功率、视觉/结构一致率，人工复核负号、指数、分母等关键变化。规范化仅消除不改变结构的空格/等价排版命令；不以代数等价代替忠实转写。
- 布局报告 GT块召回、重复块和位置匹配（IoU阈值0.5，拆分/合并块有固定规则）；阅读顺序按GT偏序的可比较块对计算倒序率，避免对独立图注强加任意顺序。
- 全量解析成功率以全部提交输入为分母；有效页/区域、失败页/区域、转换失败、截断和超时分别计数。另给“成功返回内容内的识别质量”，但它不能替代端到端质量。
- 可读GT页/区域失败时预测按空串计算，全部GT字符计删除；已有输出中多出的字仍计插入。空GT不用CER除零，改报新增文字数和假阳性页率；不可辨读掩码在看预测前冻结并披露覆盖量。
- 关键 token 包括题号、选项、分值、正负号、小数/单位、化学下标、接口字段名、URL和枚举码，冻结专项清单；每个 token 逐项 exact match，不用大段正文的均值遮盖。

文本 micro CER 按全部GT字符加权；macro CER 先按页、再按来源家族汇总。同时给每个学科、场景、真实/合成条件的样本数、GT字符数和错误数。性能按成功与失败分别报告，失败在成功率中保留。保留集区间按来源家族 cluster bootstrap 计算；原件家族不足20个时明确区间不稳定，不把数百个同页变体当独立样本。保留集一旦用于调整参数或修复针对该样本的问题，即成为开发/回归集；后续盲测需新独立保留材料，或明确只作已知集回归。

### 9.3 建议的冻结验收门槛

以下门槛适用于干净可读、通过转换保真检查的输入；退化/真实采集单独分层。先在 development 检查可操作性，再冻结门槛与配置运行 holdout。

| 项目 | 初始质量门槛 |
|---|---|
| 全量源/页/产物完整性 | 31 个主候选全部有终态；有效输入无静默漏页；页、区域、资源100%对账；失败不得记成功 |
| 干净中文正文 | micro CER ≤1%，页级 macro CER ≤2%；按学科分别报告，不以总分抵消整科失败 |
| 干净英文正文 | micro CER ≤0.5%，WER ≤2%；页级 macro CER ≤1% |
| 中英技术正文 | micro CER ≤1%；冻结关键字段/token exact match 100%，普通代码块另报逐块EM |
| 全部文字覆盖 | GT文本块召回 ≥99%；冻结的页眉/脚注/题号/图中文字专项没有整类遗漏；关键块100%覆盖 |
| 关键题面内容 | 冻结的题号、选项、分值、数值、符号专项100%正确；发现影响解题语义的错误则该专项失败 |

| 阅读顺序 | 双栏/材料-题目等偏序正确率 ≥99%；不得出现整栏交叉或跨页/跨文档串内容 |
| 空白/纯图负例 | 20个固定负例没有无来源的正文/答案；纯图中本来有字的部分不能排除 |
| Markdown/资源 | 所有引用可解析；MD/TXT/JSON可追溯到同一页/区域，没有空图片占位和静默丢图 |
| 真实手写 | 达到30页/10书写者后，建议CER ≤5%、页级macro ≤8%；题意关键字/公式结构专项另审，未达则不开放自动使用 |
| 当前4份作文 | 4份均完成全量GT和输出对账；逐份CER、漏行、涂改、空白幻觉、布局/分块错误全部披露；沿用≤5% CER作为小样效果参考 |

如果印刷文本通过而真实手写仍 GAP，最终结论只能覆盖已验收的印刷场景。门槛严格不代表预言模型能够达到；未达到时保留实际错误与限制，先定位原因，不通过归一化/删样本降低错误率。

## 10. 性能、稳定性与故障测试

### 10.1 测量边界

端到端延迟从任务被接纳至 JSON/TXT/MD/资源全部写入完成；队列等待、PDF栅格化、CPU布局、裁剪、区域推理、组装和持久化分别计时。另报区域 TTFT/生成时间（有真实流式观测时才报告）、输入/输出token与区域/页大小。不能用SDK收到最终响应的时间冒充TTFT。

吞吐按完整批次墙钟与完成页数计算，同时报告有效成功页/秒及全部提交页/秒、失败数。不得把各区域耗时相加当文档墙钟，或只统计成功且输出短的请求。

冷启动包括进程启动、权重加载、JIT/图捕获和首份解析；至少3次独立进程启动。热运行先用独立开发样本预热，预热不计分。标准与 DSpark 的缓存策略、分辨率、采样、裁剪、并发、输入顺序和完成边界保持一致；冷缓存/缓存复用另列，不能混在同一吞吐表。

### 10.2 测试阶梯

| 编号 | 工作负载 | 最小执行量 | 检查与停止条件 |
|---|---|---|---|
| P01 | 标准解码区域并发1/2/4 | 同一固定100个混合区域，每档3次 | 资源/延迟/吞吐随并发变化；最多4活跃区域；质量不变成截断 |
| P02 | 完整文档页级串行 | 全部31主源一次；3PDF完整49页 | 长文档、各学科、全页预算与漏块；返回产物/页数对账 |
| P03 | 稳态完整文档页 | 三原PDF共同49张P0页图循环，60分钟接纳窗后按原deadline排空，至少300个终态页 | GPU/CPU/RSS/温度/磁盘采样1秒；尾延迟、错误与资源趋势 |
| P04 | 超载与排队，仅HTTP包装交付时必选 | 同时提交10文档，重复3轮；慢客户和取消 | 包装层1运行+8等待，其余429；CLI交付不以此作为必选门 |
| P05 | 重复同页与不同页 | 各30页相同次数，单独报告 | 缓存收益不能冒充未知页面处理速度；检查跨请求内容污染 |
| P06 | 冷启动/重启 | 至少3次服务启动，含1次待处理任务场景 | 真实就绪、首请求、任务终态/恢复、无双写 |

样本不足200个有效观测时不发布 p95 的稳定结论；p99 至少1000个观测后才作为可用尾延迟估计，否则写样本不足并报最大值。所有分位数注明是区域、页还是文档，成功/失败分母与区间。

运行硬门：无 OOM、无静默截断、无无界排队、有效输入无未解释失败；预热后GPU峰值至少留2 GiB实际余量；CPU/RSS在相同工作负载下达到平台，不出现持续增长。按静置后重复负载比较RSS，若60分钟增长超过初始稳态的10%且超过512 MiB，需调查并在更长复测中判定；正常有界缓存要列明，不直接命名为泄漏。

用户尚未给生产吞吐/延迟 SLO，本轮交付实测容量曲线与可承载请求速率，不预填“4090每秒多少页”。正式业务上线前，将测得结果与业务峰值/延迟目标单独对账；工程验证通过不自动证明未知的业务容量需求。

### 10.3 异常与恢复矩阵

| 编号 | 故障输入/注入 | 预期 |
|---|---|---|
| F01 | 损坏PDF、截断文件、伪造扩展名、无效图片 | 明确输入错误，无无限重试，不产生成功终态 |
| F02 | 加密PDF：无密码、错密码、正确密码受控路径 | 前两者明确拒绝；支持正确密码时不落盘密码、不记日志 |
| F03 | 超大小/页数/像素，解压后巨大图片 | 渲染前校验可判边界，渲染进程有内存/时间限制；不拖垮其他任务 |
| F04 | 空PDF、空白页、纯图、混合方向/不同页尺寸 | 各页独立明确状态；不漏页、不幻觉填字 |
| F05 | 人为极小max_tokens、16K上下文边界、超长表格 | `length`/context溢出被记录；分块策略有映射；未恢复完整不得成功 |
| F06 | 识别HTTP超时、连接中断、临时5xx、不可恢复4xx | 仅可恢复错误有限重试，记录首错/最终错；总deadline生效 |
| F07 | 文档中间1页/1区域失败、组装失败、图片资源写失败 | 文档partial_failed/failed，列失败页/块；不输出貌似完整的成功文档 |
| F08 | 运行时停止识别服务/布局子进程，随后重启 | 控制失败范围，恢复后新任务可用；旧任务状态明确 |
| F09 | 取消排队/运行任务、客户端断连、同文件重复提交 | 不串结果、不覆写；活动进程回收，重复执行按run隔离 |
| F10 | 输出目录只读、限定临时目录磁盘配额不足 | 原子最终文件、不写半个成功文件；只在专用测试目录注入，不填满宿主盘 |
| F11 | 首次/再次启动禁止联网 | 模型、布局、字体/JIT依赖均完整；失败列明尚缺资源 |
| F12 | 容器重启，已有完成页；HTTP包装重启仅交付该层时必测 | CLI明确旧运行终态且可用新run重跑；若实现任务包装，再验其恢复合同；回滚后标准解码仍可运行 |

每种故障至少一次，涉及重试/取消/恢复的用例至少3次。故障只注入本次测试进程/容器/目录，不停止现有业务容器，不制造宿主全局 OOM/磁盘满。

## 11. DSpark 评估与采用条件

当前执行状态（2026-10-29）：`NOT_ADMITTED_QUALITY_GATE`。质量门尚未PASS；下载/权重校验和脚本已准备，不代表执行过GPU加速或满足本节进入条件。

只有两模型标准解码基线及横向比较完成，且Mini部署、全页完整性、质量和稳定性门槛通过后才进入本阶段。下载同一release匹配draft，核对主/draft配置及全部文件哈希；不混用不同版本。DSpark精确启动参数与工具链见 [deployment-details.md](deployment-details.md)。

实验保持BF16、16K、4区域、0.65、CPU布局、相同最终配置与适配；先测区域1/2/4并发，再测端到端完整页。先确认draft已加载且有draft/accepted token等实际指标或引擎证据，不能仅凭命令行出现speculative配置宣称加速启用。

同一固定混合测试集按统一合同的预先冻结平衡AB/BA块运行标准A/DSparkB，至少3对独立重复；不同时运行两个完整GPU服务。每次切换单独记录加载/预热，缓存条件一致。另复跑全页保留集与关键公式/字段/空白负例。

对每个来源配对比较全文、关键字符、公式/表格、输出长度、finish_reason、失败率及延迟。标准解码也做自重复以测正常输出变动；不要求未经证明的逐字确定性，但所有输出差异需要归因，不能只比较相似度或总token数。

建议采用门槛：

1. 没有新增关键字段/公式语义错误、漏页、截断、失败或空白幻觉，绝对质量仍达到第9节门槛。
2. 总体/分层CER的配对变化上界不超过0.1个百分点；公式/表格指标下降不超过0.5个百分点，样本不足以支撑区间时继续保留标准解码，不写“不退化已证实”。
3. 混合完整页端到端吞吐中位数至少提高15%，按原件配对的95%区间下界高于1.0倍；p95延迟不退化超过5%，不能只以解码token/s收益采用。
4. 峰值资源和稳定性满足原硬门，draft加载与接受指标可复核。

任一不满足，结果为 `dspark_accepted=false`，保留标准解码作为交付服务。不要用官方5090上的加速比例代替29的实测，也不为了采用加速而提高显存预算、缩短输出或换更容易的页。

### 12.1 运行与回滚

服务以独立容器/专用用户运行，GPU仅授权给识别容器；CPU布局/转换器分环境、原件只读、输出目录限权。只绑定本机入口；运行日志保留request_id和状态，原始内容放受限验收产物，不写普通访问日志。

配置/镜像/源代码/补丁/主模型清单一起组成不可变release。运行器只选择一个release；健康检查之外增加固定真实图片的部署后验证。新release不就绪则停新容器，恢复前一个已验收镜像和配置。DSpark回滚只移除draft/speculative设置并恢复原baseline配置，不重新下载或改写主模型。

回滚验收至少一次：标准服务成功解析 → DSpark或新配置启动失败的受控模拟 → 恢复baseline → 同一完整文档再次通过。原件、金标、历史run和失败证据全部保留。模型/cache清理仅在对应release不再使用且哈希归档完成后进行。
