# 目标、基线与可比较的收益

## 1. 目标不是一个峰值

受保护的主profile必须同时保留：200192上限、真实196K附近输入+输出、medium采样、原模型主干/codec合同、Java工具闭环、长期会话恢复和原运维边界。任何降到200192以下、换主权重量化、关闭thinking、CPU offload、隐藏截断的结果，独立标注tradeoff，不能作为“更快同产品”。

**决策记录（2026-09-09，lky）**：受保护容量由生产现值262144下调为**200192**。原因：DFlash2 W8 companion在262144预算内显存不成立（空闲1509MiB，常驻净增≈1734MiB+工作区）；按fork自身load-log斜率rk4v4-e8≈26.4KB/token，降到200192释放≈1597MiB，预计峰值后余量≈1.2GiB，满足§3资源硬门且无需退到draft W4。262144不再是硬门：候选若仍能装下262144，作为事实记录，不作为通过条件；同一显存预算不能同时给rk8v4与DFlash2，二选一。本包其他位置出现的“受保护262144/262K”均以本节为准。

## 3. 两级性能门

**工程补丁门**：主要桶**≥8个配对测量**（ABBA布局、跨两次启动；`tools.metrics.MIN_GATE_PAIRS`），预登记主要桶的收益95%下界≥3%，其他主要桶不得>3%回退，任务wall不得>2%回退。区间取percentile bootstrap与log-ratio Student-t区间中更保守者（`paired_summary.ci95_low`）；n=5的percentile bootstrap只有3125种重采样、区间偏窄，不再作为门的依据。同一harness同一桶必须先跑baseline-vs-baseline（A/A）得到噪声底`aa_noise_abs=max|ratio−1|`，>3%时测量链本身`BLOCKED`，不能报任何收益。`candidate_gate`必填`paired_n`与`aa_noise_abs`。小于测量噪声仅记为“未证明收益”。

**筛选预算的算术**（`22 §4.6`）：184K桶一个样本≈105s（冷prefill 94s + 1024 token解码≈11s），8配对ABBA=16次≈28min，加16次baseline/candidate切换重启（≈40s/次）≈11min → **一个184K桶≈40min**。所以“一小时筛选”一轮只做一个长度桶（docs/12 §2）。

**新算法投入门**：在训练/调参集外的8条固定轨迹上，主要产品桶期望≥10%吞吐或≥10%任务wall改善，且不靠输出量变少掩盖错误。若只能改善copy桶，归为copy-only profile，不推广默认。

**容量硬门**：200192 profile以实际prompt约196000、输出至少2048验证（总含模板≤200192；`tools/metrics.py::PROTECTED_CAPACITY`）。启动成功不算；不可静默截断。184K持续生成用于日常性能，不冒充满容量验证。

**资源硬门**：无OOM/非法访问；真实负载峰值后余量≥512MiB，推荐≥1GiB。必须记录当前同卡其他进程、功耗/频率、显存峰值；不能通过停止未授权工作负载来凑成绩。

## 4. 不足以证明质量等价的测试

Java3/3是兼容性smoke，不是有统计能力的质量实验；needle同样只能证明一类检索。对于纯bit-equivalent改动，以数学/状态oracle为首；改变target算术/codec/主权重的补丁，必须另跑至少30个冻结的Java契约/代码细节用例和既有更大质量集，并报告配对失败及不确定性。若样本不足，状态只能是`QUALITY_NOT_ESTABLISHED`，不能声称“不降智”。

## 5. 停止追逐不相关指标

不以SSE帧率、输出字符数、driver显示CUDA版本、模型文件磁盘大小、suffix预测未来答案命中率替代GPU证据。无可比原始采集器的旧结果保留为历史参考，不与新数据作精确百分点推断。
