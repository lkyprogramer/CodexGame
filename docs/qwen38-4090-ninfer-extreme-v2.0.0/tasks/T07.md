# T07 — W8合法验证路径、资源完整性与DFlash2收益前置门

**依赖**：T01。**路线**：dflash。**初始状态**：NOT_STARTED。

## 范围与接口

W8 physical/liveQ 1..8，24Q/4KV/d256 →明确route+workspace+输出；先正确后优化。**本任务同时是DFlash2链的第一道门**：DFlash2相对MTP的实质收益只能来自K=7的宽度（`../docs/07 §9`、`../docs/22 §4.1`），而44a的small-T专用路径只到T=6（`src/CMakeLists.txt:278`；`gqa_attention_decode.cu:19/239/243`），所以W8路径在184K下的每轮额外耗时`Δ_w8`决定T09/T10是否值得启动。它不依赖T04的采样合同，也不需要DFlash2权重：用现有op测试框架喂8行query即可测kernel级成本。

### 什么**不是**T07（2026-09-10按一次误执行补充）

- 对现有MTP制品`qwen3_8_27b.ninfer`启动`--spec dflash --draft-tokens 8`不是T07的任何步骤。它必然报`DFlash is not supported by this target`：44a的qwen3_8 target `enable_dflash=false`（`round_state.h:26`），制品也没有DFlash2 companion（`../docs/22 §2.2`）。这个报错是已知事实，不是T07的测量结果，也不能据此写`未过门`/`NO_GO`。
- T07没有引擎级、HTTP级动作。它的产出全部来自：改`src/CMakeLists.txt:278`的small-T编译范围（或做generic route）→ 重新构建 → 用`tests/ops/test_gqa_attention.cpp`框架对同一rk4v4-e8缓存视图喂T=4与T=8行query → 得`Δ_w8`。没有构建过W8路径就没有`Δ_w8`，状态只能是`BLOCKED: W8路径未构建`。
- companion（T08）/persistence（T10）本来就不在本任务范围内，不得列为本任务"未做"项。
