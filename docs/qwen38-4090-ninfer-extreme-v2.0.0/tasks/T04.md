# T04 — 扩展现有精确采样器：ProposalBatch合同与Sparse16 q

**依赖**：T02。**路线**：algorithm。**初始状态**：NOT_STARTED。

## 范围与接口

消费contracts/proposal_contract.h；产出PointMass、Sparse16、NativeMtp三类q说明及verify授权/partialcommit接口。

**已有的不要重写**（`../docs/22 §2.2`）：`src/ops/kernel/speculative_round.cuh:60-68`已是T>0的distribution-correct speculative rejection sampling——one-hot（greedy）draft按`p_i(d)`接受、首拒从masked residual重采样、末列bonus。这正是docs/05 §2的PointMass路径与现网MTP的NativeMtp路径。本任务真正新增的是**Sparse16**：DFlash2 top-16 selector沿实际前驱的条件q（非one-hot、非全vocab），以及把三类q统一进ProposalBatch合同（每行`origin`与q类型），供T06（PointMass延长行）和T10（Sparse16）复用。

读取设计：`../docs/03-architecture-and-state.md`、`../docs/05-exact-sampling.md`、本路线专题文档。

## 反例与验收断言

1. p=[.7,.2,.1],q=[.2,.7,.1]纠偏后边际严格=p
2. onehot proposal命中/拒绝和disjoint support
3. p=q无reject分支，不能以uniform做epsilon补丁
4. EOS/stop/cancel使N变小但未提交tail不入cache
5. 现有one-hot（MTP）路径在扩展前后同seed逐位一致；Sparse16 q缺任一项或未归一化时拒绝，不用uniform补
