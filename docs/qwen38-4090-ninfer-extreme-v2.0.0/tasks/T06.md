# T06 — Suffix链延长 + 现有MTP（v1零bridge；v2条件启动）

**依赖**：T04, T05。**路线**：suffix。**初始状态**：NOT_STARTED。

## 范围与接口

**v1（本任务主体）**：MTP resident照常产出`d1..d3`并前进私有状态；CPU `SuffixIndex::lookup([committed…, d1, d2, d3])`命中时把链延长到K≤5（W≤6）；延长行q=PointMass走`speculative_round.cuh`现有exact rejection sampling；ProposalBatch每行带`origin ∈ {mtp, suffix_ext}`。未命中时与现网逐字节相同。**不做bridge、不改MTP状态、不加权重、不加kernel**（`../docs/06 §2`）。

**v2（仅当v1的`suffix_hit_rate`与`extra_committed_per_round`证明长重复存在）**：alternating-source整条替换 + `mtp_bridge_and_propose` catch-up。v2的启动写进decision.json，不在本任务默认范围。

### 什么**不是**v1（2026-09-10按一次误执行补充）

- 对**未改动**的44a二进制跑`--spec mtp --draft-tokens 5`（或任何`--draft-tokens`值）不是v1，也不是v1的近似。那只是让MTP head自回归多跑2步、全部由MTP出草稿；v1的W=6是**3个MTP草稿 + ≤2个suffix延长**，延长部分零GPU draft成本，且只在CPU索引命中时出现。`--draft-tokens 6`被拒是`docs/serving.md:571`（MTP 1..5）的合同内行为，不是待修bug。
- 没有`SuffixIndex`（T05）与可变`live_proposals`（本任务）的C++实现之前，本任务**没有可测对象**；此时唯一合法状态是`BLOCKED: T05/T06 未实现`，不得写`候选否决`或`NO_GO`。
- 5–32 token输出、`reasoning_effort=none`、`temperature 0.2`的HTTP探针不构成decode吞吐样本：`predicted_per_second`在一两轮内量的是固定开销。有效样本按`../docs/12 §2`（实际输出≥1024、medium采样、4K/64K/184K桶、≥8配对ABBA、先A/A）。
- 2026-09-09那组`output/qwen38-4090-compare/extreme_v2`数据唯一可保留的信息：W=6 verify + 5步MTP draft的一轮比W=4的一轮贵≈13–15ms，说明额外行不免费；但它分不开draft步成本与verify行成本，这个分解归T07的kernel微基准。

## 反例与验收断言

1. v1未命中路径：与现网同seed同请求的target输出、状态、round计数逐字节相同（负对照回归）
2. 在`d1..d3`任一处被拒时延长部分自然作废，不产生额外verify、不污染state

4. 无额外权重，200192仍能装且控制API不变；lookup开销使负对照退化>3%则v1不合
