# Utility/restore：保留性能实验，限制策略范围

utility可以在单请求中选择更合适的已合格backend/width，也可以在真实混合负载减少调度/restore成本；不能笼统说只有并发才有用。先测实际选择成本与输入变动，没有可选route或成本稳定则不值得增加策略。

先一条固定规则或小表与原策略AB；采样/状态/容量资格仍由原执行权威决定。CPU决策、统计同步、cache miss和恢复时间纳入完整wall。只主张单请求收益时不做多租户QoS/fairness平台；主张混合负载收益时才补最小混合负载。无需等待所有高级草稿或H5生产发布。
