## Interfaces

**Consumes：** T00的本机路径；references/source-lock.json。

**Produces：** 完整源码SHA、镜像digest、Cargo.lock与serve依赖、wheel/库SHA；源树干净的poc/sm89-w4a16-64k分支。

## 实施与测试步骤

- [ ] **Step 1 — 写失败测试。** 在本任务test文件中把以下行为做成断言，至少包含一个故意破坏数据/元信息的负例，不用“空数组也通过”的fixture。

- git rev-parse HEAD等于固定SHA。
- 离线模式无网络也能进行CPU verifier构建。
- 记录实际动态加载cuBLAS路径，不能同时混入另一套wheel版本。

- [ ] **Step 2 — 验证RED。** 在固定源树中执行：

```bash
python3 -m unittest discover -s tests/sm89 -p 'test_T01.py' -v
```

首次应因本任务尚未实现的合同而失败。若失败来自拼写/导入环境，先修测试基础；缺GPU应BLOCKED，不把错误日志当数值失败。T00/T01没有GPUtest时先运行`bash scripts/self_check.sh`和文档中的只读命令，并保存actual findings。

- [ ] **Step 3 — 最小实现。** 联网机准备git bundle和Cargo vendor、wheelhouse、镜像tar；目标机校验后导入。根workspace与kern-serve分别cargo build --locked --offline。固定CUDA13.0 API及同一cuBLAS13库来源；不要修改宿主610驱动或全局CUDA symlink。

- [ ] **Step 4 — 验证GREEN与GPU Gate。** 重跑单测；涉及GPU的任务在授权维护窗口中执行固定接口：

```bash
python3 tests/sm89/run_gate.py --gate T01 --config work/poc.local.json \
  --out work/records/T01/gate.json
```

此命令由T03统一runner驱动各任务真实实现。它不能仅返回预设JSON；必须记录实际子命令、退出码、device和输出文件hash。T00–T02只运行对应CPU工具，不要求尚未创建的runner。

- [ ] **Step 5 — 审阅并提交。** 检查改动没有触碰production路径、没有在runtime硬编码模型名、没有放宽数值阈值。保存`git diff --stat`和原始日志，再提交单一任务：

```bash
git status --short
git diff --check
# 仅add本任务列出的源码/测试；不要git add权重、凭据或整个results目录。
git commit -m 'feat(sm89): T01 冻结源码与离线构建环境'
```

## 验收/失败处理

上方断言全部成立且证据可重新运行后才更新`work/task-status.json`。失败保留日志、把状态写FAIL/BLOCKED；本任务GPU子进程退出，交由维护guard恢复原NInfer。不要“为了推进下一步”跳过本任务。
