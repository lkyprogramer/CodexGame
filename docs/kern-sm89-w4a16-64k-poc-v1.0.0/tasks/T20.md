**Architecture:** 不破坏通用runtime/provider边界；原模型与生产资产只读；GPU任务独占。

**Spec:** `docs/00-master-plan.md`，相关分项03–12。
**Dependencies:** T18, T19。

## Files

- `tests/sm89/test_T20.py`
- `tests/sm89/lifecycle.py`

## Interfaces

**Consumes：** controller traces、运行进程、已提交state。

**Produces：** cancel→retry、A/B/A、context overflow、错误输入、load/unload后的正确性结果。

统一GateResult约定：`{"id":"T20","status":"PASS|FAIL|BLOCKED|INCOMPLETE","command":[],"exit_code":0,"evidence":[{"path":"relative/path","sha256":"64hex"}]}`。PASS须有实际命令和非空证据；GPU缺失不得返回PASS。`tests/sm89/run_gate.py`由T03建立，T00–T02用本包CPU工具完成。

## 实施与测试步骤

- [ ] **Step 1 — 写失败测试。** 在本任务test文件中把以下行为做成断言，至少包含一个故意破坏数据/元信息的负例，不用“空数组也通过”的fixture。

- 没有跨会话数据污染。
- 每请求唯一finish/错误终态，无silent stop。
- 取消后服务仍ready、显存回可解释平线。

- [ ] **Step 2 — 验证RED。** 在固定源树中执行：

```bash
python3 -m unittest discover -s tests/sm89 -p 'test_T20.py' -v
```

首次应因本任务尚未实现的合同而失败。若失败来自拼写/导入环境，先修测试基础；缺GPU应BLOCKED，不把错误日志当数值失败。T00/T01没有GPUtest时先运行`bash scripts/self_check.sh`和文档中的只读命令，并保存actual findings。

- [ ] **Step 3 — 最小实现。** 在prefill和decode各取消一次，再发有效请求；独立A/B/A会话用不可混淆needle和输出；检查KV及state引用释放。超过窗口4xx不是CUDA失败；绝不把不完整state发布为可恢复checkpoint。加入重复生命周期轮次，查看资源是否持续增长。

- [ ] **Step 4 — 验证GREEN与GPU Gate。** 重跑单测；涉及GPU的任务在授权维护窗口中执行固定接口：

```bash
python3 tests/sm89/run_gate.py --gate T20 --config work/poc.local.json \
  --out work/records/T20/gate.json
```

此命令由T03统一runner驱动各任务真实实现。它不能仅返回预设JSON；必须记录实际子命令、退出码、device和输出文件hash。T00–T02只运行对应CPU工具，不要求尚未创建的runner。

- [ ] **Step 5 — 审阅并提交。** 检查改动没有触碰production路径、没有在runtime硬编码模型名、没有放宽数值阈值。保存`git diff --stat`和原始日志，再提交单一任务：

```bash
git status --short
git diff --check
# 仅add本任务列出的源码/测试；不要git add权重、凭据或整个results目录。
git commit -m 'feat(sm89): T20 取消、错误与会话周转'
```

## 验收/失败处理

上方断言全部成立且证据可重新运行后才更新`work/task-status.json`。失败保留日志、把状态写FAIL/BLOCKED；本任务GPU子进程退出，交由维护guard恢复原NInfer。不要“为了推进下一步”跳过本任务。
