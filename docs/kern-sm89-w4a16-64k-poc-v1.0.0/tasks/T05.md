# T05：原compressed-tensors到Marlin的可复核重排 — Implementation Plan

> 执行者先读对应设计文档与AGENT_START.md。下列源码/测试文件是本任务要创建或修改的路径，不表示本交付已完成GPU实现。

**Goal:** 原compressed-tensors到Marlin的可复核重排，输出可独立复核的成果。
**Architecture:** 不破坏通用runtime/provider边界；原模型与生产资产只读；GPU任务独占。
**Tech Stack:** Python/Rust/CUDA；固定SM89/W4A16/BF16activations/FP32GDN/no-spec。
**Spec:** `docs/00-master-plan.md`，相关分项03–12。
**Dependencies:** T03, T04。

## Interfaces

**Consumes：** oracle实际加载后的packed weight/scales/gidx；量化源metadata。

**Produces：** export清单：每个物理buffer的SHA/codec/layout/padding/semantic axes，与源tensor映射。

统一GateResult约定：`{"id":"T05","status":"PASS|FAIL|BLOCKED|INCOMPLETE","command":[],"exit_code":0,"evidence":[{"path":"relative/path","sha256":"64hex"}]}`。PASS须有实际命令和非空证据；GPU缺失不得返回PASS。`tests/sm89/run_gate.py`由T03建立，T00–T02用本包CPU工具完成。

## 实施与测试步骤

- [ ] **Step 1 — 写失败测试。** 在本任务test文件中把以下行为做成断言，至少包含一个故意破坏数据/元信息的负例，不用“空数组也通过”的fixture。

- 全部16码值、group127/128/129、尾tile、零scale有测试。
- 导出回到oracle的线性输出与原运行一致。
- 本机CPU峰值受控，不能全量反量化27B占满64GB。

- [ ] **Step 2 — 验证RED。** 在固定源树中执行：

```bash
python3 -m unittest discover -s tests/sm89 -p 'test_T05.py' -v
```

首次应因本任务尚未实现的合同而失败。若失败来自拼写/导入环境，先修测试基础；缺GPU应BLOCKED，不把错误日志当数值失败。T00/T01没有GPUtest时先运行`bash scripts/self_check.sh`和文档中的只读命令，并保存actual findings。

- [ ] **Step 3 — 最小实现。** 从oracle真实repack调用取得其结果，流式/分层导出；小CPU参考用于16码值与group边界。不要凭int32元素推定logical参数。保存repack版本标识，禁止同一buffer重复repack。只导出实际语言provider需要的权重。

- [ ] **Step 4 — 验证GREEN与GPU Gate。** 重跑单测；涉及GPU的任务在授权维护窗口中执行固定接口：

```bash
python3 tests/sm89/run_gate.py --gate T05 --config work/poc.local.json \
  --out work/records/T05/gate.json
```

此命令由T03统一runner驱动各任务真实实现。它不能仅返回预设JSON；必须记录实际子命令、退出码、device和输出文件hash。T00–T02只运行对应CPU工具，不要求尚未创建的runner。

- [ ] **Step 5 — 审阅并提交。** 检查改动没有触碰production路径、没有在runtime硬编码模型名、没有放宽数值阈值。保存`git diff --stat`和原始日志，再提交单一任务：

```bash
git status --short
git diff --check

git commit -m 'feat(sm89): T05 原compressed-tensors到Marlin的可复核重排'
```
