## Interfaces

**Consumes：** A0 oracle与A1 Kern eager，冻结相同token ids/packed weights。

**Produces：** 至少512teacher-forced positions的logits/state结果、差异首Op、KL/margin报告。

统一GateResult约定：`{"id":"T11","status":"PASS|FAIL|BLOCKED|INCOMPLETE","command":[],"exit_code":0,"evidence":[{"path":"relative/path","sha256":"64hex"}]}`。PASS须有实际命令和非空证据；GPU缺失不得返回PASS。`tests/sm89/run_gate.py`由T03建立，T00–T02用本包CPU工具完成。

## 实施与测试步骤

- [ ] **Step 1 — 写失败测试。** 在本任务test文件中把以下行为做成断言，至少包含一个故意破坏数据/元信息的负例，不用“空数组也通过”的fixture。

- 与同W4A16 oracle的pack/索引完全一致。
- 非近平局大误差/NaN/Inf明确失败。
- 未输出数组或空case不能算通过。

- [ ] **Step 2 — 验证RED。** 在固定源树中执行：

```bash
python3 -m unittest discover -s tests/sm89 -p 'test_T11.py' -v
```

首次应因本任务尚未实现的合同而失败。若失败来自拼写/导入环境，先修测试基础；缺GPU应BLOCKED，不把错误日志当数值失败。T00/T01没有GPUtest时先运行`bash scripts/self_check.sh`和文档中的只读命令，并保存actual findings。

- [ ] **Step 3 — 最小实现。** 分片存logits，选定GDN层和checkpoint；比较固定prompt与teacher-forced下一tokens。先allclose/bit-contract，再near-tie诊断。自由生成分叉后的tensor不能比较。数值阈值按docs08锁定，不通过时定位而非放宽。

- [ ] **Step 4 — 验证GREEN与GPU Gate。** 重跑单测；涉及GPU的任务在授权维护窗口中执行固定接口：

```bash
python3 tests/sm89/run_gate.py --gate T11 --config work/poc.local.json \
  --out work/records/T11/gate.json
```

此命令由T03统一runner驱动各任务真实实现。它不能仅返回预设JSON；必须记录实际子命令、退出码、device和输出文件hash。T00–T02只运行对应CPU工具，不要求尚未创建的runner。

- [ ] **Step 5 — 审阅并提交。** 检查改动没有触碰production路径、没有在runtime硬编码模型名、没有放宽数值阈值。保存`git diff --stat`和原始日志，再提交单一任务：

```bash
git status --short
git diff --check

```
