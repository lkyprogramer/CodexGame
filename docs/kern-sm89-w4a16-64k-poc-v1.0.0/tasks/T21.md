## 实施与测试步骤

- [ ] **Step 1 — 写失败测试。** 在本任务test文件中把以下行为做成断言，至少包含一个故意破坏数据/元信息的负例，不用“空数组也通过”的fixture。

- 短4K–8K ≥50tok/s、64K ≥20tok/s各3次，输出≥2048。
- 任何提前停/实际长度不符为INCOMPLETE或FAIL而非删样本。
- 列出NInfer spec/precision/thinking差异，不假称同算法比较。

- [ ] **Step 2 — 验证RED。** 在固定源树中执行：

```bash
python3 -m unittest discover -s tests/sm89 -p 'test_T21.py' -v
```

首次应因本任务尚未实现的合同而失败。若失败来自拼写/导入环境，先修测试基础；缺GPU应BLOCKED，不把错误日志当数值失败。T00/T01没有GPUtest时先运行`bash scripts/self_check.sh`和文档中的只读命令，并保存actual findings。

- [ ] **Step 3 — 最小实现。** 用build_prompts生成4096/32768/65536实际ids。吞吐测试允许ignore_eos并仅用于速度；检索和Agent正常EOS。以accepted_target_tokens/engine_decode_wall计算，不以SSE帧数或requested max_tokens代替。oracle与candidate串行，保留同一语料。

- [ ] **Step 4 — 验证GREEN与GPU Gate。** 重跑单测；涉及GPU的任务在授权维护窗口中执行固定接口：

```bash
python3 tests/sm89/run_gate.py --gate T21 --config work/poc.local.json \
  --out work/records/T21/gate.json
```

此命令由T03统一runner驱动各任务真实实现。它不能仅返回预设JSON；必须记录实际子命令、退出码、device和输出文件hash。T00–T02只运行对应CPU工具，不要求尚未创建的runner。

- [ ] **Step 5 — 审阅并提交。** 检查改动没有触碰production路径、没有在runtime硬编码模型名、没有放宽数值阈值。保存`git diff --stat`和原始日志，再提交单一任务：

```bash
git status --short
git diff --check
# 仅add本任务列出的源码/测试；不要git add权重、凭据或整个results目录。
git commit -m 'feat(sm89): T21 同口径性能测量与初步竞争性'
```
