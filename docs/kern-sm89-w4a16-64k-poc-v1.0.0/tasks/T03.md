**Architecture:** 不破坏通用runtime/provider边界；原模型与生产资产只读；GPU任务独占。
**Tech Stack:** Python/Rust/CUDA；固定SM89/W4A16/BF16activations/FP32GDN/no-spec。
**Spec:** `docs/00-master-plan.md`，相关分项03–12。

## Interfaces

**Consumes：** T02模型锁；固定可加载W4A16的vLLM环境。

**Produces：** GateResult{id,status,command,exit_code,evidence[]}；相同token输入、packed buffer、selected activations/logits/state NPZ与metadata。

统一GateResult约定：`{"id":"T03","status":"PASS|FAIL|BLOCKED|INCOMPLETE","command":[],"exit_code":0,"evidence":[{"path":"relative/path","sha256":"64hex"}]}`。PASS须有实际命令和非空证据；GPU缺失不得返回PASS。`tests/sm89/run_gate.py`由T03建立，T00–T02用本包CPU工具完成。

## 实施与测试步骤

- [ ] **Step 1 — 写失败测试。** 在本任务test文件中把以下行为做成断言，至少包含一个故意破坏数据/元信息的负例，不用“空数组也通过”的fixture。

- oracle自重复2次输出可解释，输入/weight/profile hash稳定。
- 故意破坏一项weight index能被检查发现。
- 缺模型/驱动/正确dtype不返回PASS。

- [ ] **Step 2 — 验证RED。** 在固定源树中执行：

```bash
python3 -m unittest discover -s tests/sm89 -p 'test_T03.py' -v
```

首次应因本任务尚未实现的合同而失败。若失败来自拼写/导入环境，先修测试基础；缺GPU应BLOCKED，不把错误日志当数值失败。T00/T01没有GPUtest时先运行`bash scripts/self_check.sh`和文档中的只读命令，并保存actual findings。

- [ ] **Step 3 — 最小实现。** 用inspect/--help确认当前vLLM参数，再实现reference driver。显式no-spec、BF16act、FP32GDN、BF16KV、单并发；不要运行recipe默认脚本继承FP16/KVarN。run_gate按gate id调用真实测试main，未知id/缺GPU退出78。每次导出限制当前有效slot与selected steps，避免整池拷贝。

- [ ] **Step 4 — 验证GREEN与GPU Gate。** 重跑单测；涉及GPU的任务在授权维护窗口中执行固定接口：

```bash

  --out work/records/T03/gate.json
```

此命令由T03统一runner驱动各任务真实实现。它不能仅返回预设JSON；必须记录实际子命令、退出码、device和输出文件hash。T00–T02只运行对应CPU工具，不要求尚未创建的runner。

- [ ] **Step 5 — 审阅并提交。** 检查改动没有触碰production路径、没有在runtime硬编码模型名、没有放宽数值阈值。保存`git diff --stat`和原始日志，再提交单一任务：
