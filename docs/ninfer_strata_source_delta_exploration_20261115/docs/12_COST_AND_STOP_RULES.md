# 成本模型、预算与停止规则

## 1. 净成本，不是acceptance竞赛

对一个实际round，令C为请求完成路径上的成本，Y为正式提交/可用产出；候选只有在 `C_new / C_old < Y_new / Y_old` 时才降低每正式token成本。C包含target、target head、proposal、查询、状态维护/catch-up、commit及有关服务开销。重叠的阶段不能直接求和，须由完成路径证据识别可省部分。

D1：`净节省 = 真正未执行的proposal关键路径 − 查询/索引摊销 − catch-up − 新同步/状态成本`，同时计Y变化。若仍做完原MTP再丢结果，skip节省=0，而不是“命中了一次所以省一次”。

H2：`净节省 = 原head可省成本 − sketch/选择/精排 − 额外内存与同步影响`，再加接受率变化导致的额外round。仅shortlist kernel快不代表整轮快。

当某串行必经段真实占比为f且只把该段加速s倍，理想Amdahl速度比为 `1 / ((1-f)+f/s)`。但旧profile的kernel总和/并集或不同P4合同占比不能当当前f；存在重叠/瓶颈迁移时仅作机会筛查，不是严谨收益上界。

## 2. 当前授权与未来建议

当前 `approved` 全为0，见[BudgetLedger](../templates/BudgetLedger.json)。以下只是后续可审核的建议上限；用户未批准前不得执行。

| 阶段 | 建议上限 | 达限动作 |
|---|---|---|
| R0 源码/历史核查 | 单轮4人时；不拉模型；关键身份缺失即停止 | BLOCKED_IDENTITY，不继续浏览更多引擎 |
| R0-E0可选baseline取证 | 单独批准后，建议2次engine、6请求、8192生成token、20分钟；storage先冻结 | 仅baseline，无candidate；资格不成立回BLOCKED，不借后续额度 |
| R1 离线筛查 | 每候选4人时；已有真实任务三类各20起；最多10000round用于机会估计 | 证据不足记INCONCLUSIVE，不制造数据 |
| R2 最小实现 | 仅一个候选；3个工作日的开发timebox，CPU/build额度另批准 | 超范围先review，不扩成新引擎 |
| R3 硬件资格 | 建议最多4次owned engine启动、24个生成请求、32768生成token、60分钟GPU窗口 | 任一额度耗尽即INCOMPLETE；不得借下一阶段额度 |
| R4 正式实验 | 严格6pair=12次fresh engine启动；请求上限=12×冻结任务数N；所有任务同清单 | 需执行前按清单估算并批准GPU wall/总token/存储cap；任一未填不运行 |

R3若已有有效同身份资格可复用并减少请求；若最小正确性集合装不进建议cap，先缩小候选适用合同或向用户申请明确的新预算。不能删关键失败边界以凑cap。R4另批预算，N和max_new都必须在spec冻结，不能开始后增样本。

引擎启动/加载失败、超时、OOM也计额度；GPU窗口包括该owned engine活跃的加载/资格/等待，不只累计kernel时间。计费细则由原BudgetLedger实际实现绑定，不能自己另算“有效时间”省账。

存储cap默认按本实验raw/normalized/log/临时artifact**同时保留的未压缩逻辑字节峰值**计，不用ZIP压缩后大小规避；`used.storage_bytes`记录至今保留峰值，删文件不返还已用额度。既有controller若使用其他计数语义，R0必须显式映射并经审阅冻结；语义未绑定就BLOCKED。此预算用于未来运行产物，不把本次只读研究文档生成伪装成一次引擎实验。

## 3. 硬停止

- 任何Target/state错、NaN/Inf、越界、跨请求污染、采样q不成立、错误缓存复用。
- model/codec/context/W/采样/功耗或硬件身份漂移；AAnoise缺失；observer未合格却用于推导产品收益。
- 必需证据缺失、raw被覆盖、丢事件却按0计；正式运行失败从汇总移除。
- 候选仅靠更宽窗、换权重、降上下文、挑copy格成立；这与批准合同不符。
- 当前部署/后续P3被发现已等价实现；R1无可证明收益空间。
- 预算耗尽、权限失败或需新资源。不得自行升级驱动、安装内核模块、解锁GPU或停止线上服务。

## 4. 什么时候允许重新提出

旧关闭只在原范围有效，不永久否定家族。但重提至少提供：不同机制的固定源码、当前真实瓶颈证据、与旧实现精确diff、独立预算和新的预注册合同。新的项目名、版本号、benchmark截图、换n-gram/seed/tile都不够。

本包正常终点可以是：D1离线无机会，H2现有头不热，K-PAIR已被P3覆盖，M0已部署并有旧资格。这种“没有值得做的新改动”比重新跑完旧失败矩阵更有价值。
