## Boot-Time Restore Inconsistency Analysis

### 1. Root Cause

**`restoreSession()` sets `phase = "running"` but never restores thread IDs, causing `primeCodexModelCatalog()` to create duplicate threads.**

The sequence is:
1. `restoreSession()` (line 1257) loads saved state and sets `this.phase = "running"` (line 1282)
2. `restoreSession()` explicitly clears thread state: `this.threadIds = { gameplayByAgentId: {} }` (line 1284)
3. Later, `primeCodexModelCatalog()` (line 316) runs and checks: `if (this.simulation && Object.keys(this.threadIds.gameplayByAgentId).length === 0 && !this.threadIds.builder)` (line 320)
4. This condition is **true** after restore (simulation exists, threads are empty), so it calls `startThreadsForExistingSession()` which creates **new** threads

The saved `threadIds` from `persistSession()` (line 1250) are **never restored** in `restoreSession()`.

### 2. Evidence

**In `restoreSession()` (lines 1257-1292):**
```typescript
this.phase = "running";           // line 1282 - sets running state
this.threadIds = { gameplayByAgentId: {} };  // line 1284 - CLEARS threads
this.threadToAgentId.clear();     // line 1285
```

**In `persistSession()` (lines 1241-1255):**
```typescript
const sessionSnapshot: SessionSnapshot = {
  seed: this.seed,
  tick: snapshot.tick,
  threadIds: this.threadIds,  // line 1250 - SAVED but never restored
  metrics: this.metrics.snapshot(),
  simulation: simulationState
};
```

**In `primeCodexModelCatalog()` (lines 316-326):**
```typescript
if (this.simulation && Object.keys(this.threadIds.gameplayByAgentId).length === 0 && !this.threadIds.builder) {
  await this.startThreadsForExistingSession();  // Creates NEW threads
}
```

### 3. Smallest Safe Fix

In `restoreSession()`, after restoring simulation state, also restore the thread IDs from saved state:

```typescript
// After line 1280 (after the else block), add:
if (saved.threadIds) {
  this.threadIds = saved.threadIds;
  // Rebuild threadToAgentId map
  for (const [agentId, threadId] of Object.entries(saved.threadIds.gameplayByAgentId ?? {})) {
    this.threadToAgentId.set(threadId, agentId);
  }
}
```

And remove the clearing lines (1284-1285) that overwrite the restored values.

### 4. Risks

1. **Thread staleness**: Restored thread IDs may point to threads that no longer exist (if codex server restarted). The `primeCodexModelCatalog()` check exists to handle this, but the fix changes that behavior.

2. **Race condition**: `restoreSession()` runs synchronously in `start()`, while `primeCodexModelCatalog()` is `void` (fire-and-forget). The timing between them is not guaranteed.

3. **Alternative approach**: Instead of restoring thread IDs, skip the `primeCodexModelCatalog()` thread creation when a session is restored by tracking a `restored` flag, then explicitly call `startThreadsForExistingSession()` only if needed.

---

**Recommended approach**: Add a `restored` flag in `restoreSession()` and check it in `primeCodexModelCatalog()` to prevent duplicate thread creation, while still allowing thread recreation if the codex connection is fresh.
