## 1. Root cause

The circuit breaker can be bypassed because `reconnectAttempts` is reset to `0` on the `connected` event (line 216), but a successful `session.start` or `session.reset` does **not** reset `reconnectAttempts`. This creates a race condition:

- If Codex disconnects and reconnects successfully, `reconnectAttempts` resets to 0.
- If the user then calls `session.start` while `reconnectAttempts` is still elevated from a previous failure, the counter persists.
- More critically: if `session.start` is called **after** the circuit breaker has tripped (phase = "error"), the new session inherits the stale `reconnectAttempts` value, allowing the circuit breaker to trip again immediately on the first disconnect of the new session.

Additionally, `resetSession()` (line 536-556) does not reset `reconnectAttempts`, so a session reset after failures carries forward the counter.

## 2. Evidence

**Line 216** - `connected` event resets counter:
```typescript
this.codexClient.on("connected", () => {
  this.connected = true;
  this.reconnectAttempts = 0;  // ← resets on successful connection
  this.sendSessionState();
});
```

private async resetSession(seed?: number): Promise<void> {

Add `this.reconnectAttempts = 0;` to both `startSession()` and `resetSession()`:

**In `startSession()`** (after line 470, where `preparedSeed` is cleared):

- No existing tests should break; if anything, this makes the circuit breaker behavior more predictable and testable.
