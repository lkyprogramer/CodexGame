## 结论

**主力够用，但要带工具/仓库上下文用。**

这台 Q4 3.8 在可执行编码、竞赛切片、工具调用、指令遵循、硬推理、64K 内多针检索上，都达到或超过方案门槛。它弱的是 **闭卷项目知识** 和 **思考打开时的格式洁癖**：不问仓库、只问“CodexGame 的 tickMs”，它会瞎编（50，而不是 200），还会按一般游戏引擎回答“客户端可以拥有模拟权威”。

不要用官方卡上的 90.3 LiveCodeBench / 89.2 GPQA 当这台机器的分数。本机可对齐的结论是：短码和算法题很强；仓库编辑 Python 极稳、JS 差点；当 OpenClaw 时必须把仓库读进上下文。

## 九个问题的答案

### 1. 会写短函数，还是会改仓库？

**两者都会，Python 仓库编辑已经能当主力。**

- HumanEval+ 抽样 37/41，MBPP+ 31/40。
- 自写 40 道算法题 39/40。
- T3：32 个 Python 多文件修复 **全过**（给坏实现 + 失败测试，产出 diff/全文后 apply 跑通）。
- JS 10/16，失败集中在 ESM 模块写出后测试没对上（`add`/`clamp`/`title` 等），更像 harness/格式，不完全是不会写。

机器上没有 go/javac/rustc，按方案降级为 Python 32 + JS 16。

### 2. 竞赛题和官方 90.3 差多远？

本机 40 题竞赛切片 **97.5%**，但这是自制题+隐藏单测，不是 LiveCodeBench 原题，**不能写成复现了 90.3**。能写的是：在 Q4+64K+medium 下，中等难度算法实现没有崩。差在哪要等真 LCB 切片；本轮 Full 用污染更低的自制题换了可执行性。

### 3. 指令遵循配不配 IFBench 79.5？

本机 92.6%。失败 5 题：4 个“恰好 N 条编号列表”（模型爱写加粗/段落），1 个“全程不许出现字母 i”（几乎是脑筋急转弯）。对 OpenClaw 的 JSON/schema 足够用。

### 4. 硬推理有没有被 Q4/q8 KV 打残？

没有。50 题 46 过。失败：

- Pauli σx 特征值写成 `1,-1`（对，顺序不同）
- `[x,p]` 写成 `$i\hbar$`（对，符号形式）
- 氢原子基态写成 `-14`（应 -13.6）
- Paxos majority 写成 `half`（语义对）

严格自动分 92%；宽松计大约 96–98%。不是 GPQA Diamond 原集。

### 5. 会不会编造不存在的工具？

本轮 **不会**。`rm` / `git_push` / `shell_exec` / `deploy_prod` / `write_file` / `ssh_run` 全部没有进 `tool_calls`。该调的调，闲聊 6/6 不调。

### 6. 64K 内多跳检索能不能用？关思考会崩吗？

64K 内 **能用**。56K 窗口 8/8。8K/32K 各把 authority 答成 simulation/protocol（`client_may_mutate=false` 仍对）。  
T9 里 none=20/20，**关思考在短题上没有崩**。社区 MRCRv2“关思考 43%”是 128K 8 针，本机没测 128K。现网 64K 默认 medium 仍然合理。

### 7. 对 CodexGame / Java 后端的可靠边界

| 场景 | 判断 |
|---|---|
| 中文隔离级别、索引、DDL、Kafka 幂等、Redis 锁 | **可用**（9/10 自动，`否` 被 markdown 误杀，实为 10/10） |
| Diff 评审：超时、sleep 当同步、可变默认参数 | **可用**（3/3）；客户端篡改模拟那条 JSON 解析失败 |
| 闭卷问 tickMs / AgentTurnOutput / 谁先改 protocol | **不可用**。没有仓库上下文就会编。tick 答 50；还说 Phaser 可以拥有模拟权威——这和项目铁律相反 |

OpenClaw 路径：先 `read_file` 再答。不要让它空手套项目约定。

### 8. 现网默认 medium 还要不要改 low？

**先保持 medium。** T9 上 none/low 满分、medium 15/20，但 medium 失败里：2 条安全拒绝用了 “will not / won’t”（自动漏检），2 条代码没抽出函数名，2 条又是“客户端可否权威”的闭卷胡说。  
low 在这 20 题上没有掉分，和 Dogukan“low≈medium、xhigh 不更强”一致。xhigh 18/20，不值得当默认。  
若 OpenClaw 大量短 JSON，可对那条路由关思考或 low；长程改仓库仍用 medium。

### 9. pass@2 值不值得做自动重试？

**值得，但只对可执行编码。** T1 pass@1 84% → pass@2 90%（+6 题）。T2 已经 39/40，重试没再救回那 1 题。评审/闭卷知识重试意义不大。
